# Git 命令速查

## 1. 最常用命令速查

| 命令                        | 用途                   |
| :-------------------------- | :--------------------- |
| `git status`                | 查看工作区与暂存区状态 |
| `git add .`                 | 暂存所有改动           |
| `git commit -m "msg"`       | 提交暂存区内容         |
| `git pull`                  | 拉取远程更新并合并     |
| `git push`                  | 推送本地提交到远程     |
| `git checkout -b <branch>`  | 创建并切换分支         |
| `git log --oneline --graph` | 图形化查看提交历史     |
| `git diff`                  | 查看未暂存的改动       |
| `git merge <branch>`        | 合并分支               |
| `git stash`                 | 临时暂存工作区改动     |

## 2. 仓库设置与初始化

| 命令                                          | 详细说明                                                   |
| :-------------------------------------------- | :--------------------------------------------------------- |
| `git init`                                    | 在当前目录中创建一个新的 Git 仓库。                        |
| `git init --bare <dir>`                       | 创建一个**裸仓库**（无工作目录，常用于搭建远程中央仓库）。 |
| `git config --global credential.helper cache` | 设置凭证缓存，避免每次推送都输入密码。                     |

### 2.1 克隆与配置补充

| 命令                                            | 详细说明                                                             |
| :---------------------------------------------- | :------------------------------------------------------------------- |
| `git init <dir>`                                | 在指定目录中创建一个新的 Git 仓库。                                  |
| `git clone <url>`                               | 克隆一个远程仓库到本地（包含完整历史记录）。                         |
| `git clone <url> <dir>`                         | 克隆远程仓库到指定的本地目录。                                       |
| `git clone --depth 1 <url>`                     | 浅克隆：只拉取最近一次提交的历史，适合大仓库或只想看代码的场景。     |
| `git clone --recursive <url>`                   | 克隆仓库并同时初始化所有子模块。                                     |
| `git config --global user.name "name"`          | 设置全局用户名（提交记录中显示）。                                   |
| `git config --global user.email "email"`        | 设置全局邮箱。                                                       |
| `git config --global init.defaultBranch main`   | 设置新仓库的默认分支名。                                             |
| `git config --global color.ui auto`             | 开启命令输出着色。                                                   |
| `git config --list`                             | 查看当前所有 Git 配置项。                                            |
| `git config --system` / `--global` / `--local`  | 三个配置层级（系统 / 用户 / 仓库），优先级 local > global > system。 |
| `git config --global alias.co checkout`         | 为命令设置别名（之后 `git co` 等价于 `git checkout`）。              |
| `git config --global core.editor "code --wait"` | 设置默认的提交信息编辑器。                                           |
| `git help <command>`                            | 查看某个命令的帮助文档。                                             |

## 3. 日常工作流程

### 3.1 状态检查与差异比较

| 命令                   | 详细说明                                                             |
| :--------------------- | :------------------------------------------------------------------- |
| `git status`           | 检查当前工作目录和暂存区的状态（查看未跟踪、已修改、已暂存的文件）。 |
| `git status -s`        | 以简短格式显示状态（`??` 未跟踪、`M` 已修改、`A` 已暂存）。          |
| `git diff`             | 查看**工作目录**中已修改但**尚未暂存**的文件与上次提交的差异。       |
| `git diff --cached`    | 查看**暂存区**中的文件与**上次提交**的差异。                         |
| `git diff --stat`      | 只显示每个文件增删行数的统计信息。                                   |
| `git diff HEAD`        | 查看工作目录 + 暂存区相对最近一次提交的全部差异。                    |
| `git diff --word-diff` | 在单词（Word）层面而不是行（Line）层面显示差异。                     |

### 3.2 暂存与提交

| 命令                         | 详细说明                                                             |
| :--------------------------- | :------------------------------------------------------------------- |
| `git add <file>`             | 将指定文件的更改添加到暂存区（Stage）。                              |
| `git add .`                  | 将当前目录下所有已修改和新建的文件添加到暂存区。                     |
| `git add -u`                 | 只暂存**已跟踪**文件的修改与删除（不含新增的未跟踪文件）。           |
| `git commit`                 | 将暂存区的所有内容创建一个新的提交（会打开文本编辑器输入提交信息）。 |
| `git commit -m "message"`    | 提交并直接附上提交说明信息。                                         |
| `git commit -a -m "message"` | 跳过 `git add` 步骤，直接将所有**已跟踪**文件的修改暂存并提交。      |

### 3.3 文件操作

| 命令                           | 详细说明                                                               |
| :----------------------------- | :--------------------------------------------------------------------- |
| `git rm <file>`                | 从工作目录和暂存区中删除文件。                                         |
| `git rm -f <file>`             | 强制删除（当文件在暂存区有修改时使用）。                               |
| `git rm --cached <file>`       | 仅从暂存区和版本库中删除，但保留工作目录中的文件（用于“**反追踪**”）。 |
| `git mv <old-name> <new-name>` | 重命名文件或移动文件。                                                 |

### 3.4 交互式暂存与补充命令

| 命令                             | 详细说明                                                       |
| :------------------------------- | :------------------------------------------------------------- |
| `git add -A`                     | 暂存所有更改（包括删除、修改和新增），等价于 `git add --all`。 |
| `git add -p`                     | **交互式**逐块（hunk）决定是否暂存，适合只提交部分修改的场景。 |
| `git add -i`                     | 进入交互式暂存菜单。                                           |
| `git add -n`                     | **演习**：只显示将被暂存的文件，不真正暂存。                   |
| `git commit -v`                  | 提交时在编辑器中显示详细的 diff 内容。                         |
| `git commit -m "标题" -m "正文"` | 用多个 `-m` 分别指定标题与正文，生成更规范的提交信息。         |
| `git commit --no-verify`         | 跳过 pre-commit 等钩子（hooks）直接提交。                      |
| `git commit --allow-empty`       | 创建一个空提交（常用于触发 CI 流程）。                         |

### 3.5 提交信息规范

推荐使用约定式提交，让提交历史一目了然，也便于自动生成版本号（CHANGELOG）：

| 类型       | 说明                     | 示例                       |
| :--------- | :----------------------- | :------------------------- |
| `feat`     | 新增功能                 | `feat: 添加用户登录功能`   |
| `fix`      | 修复 Bug                 | `fix: 修复分页计算错误`    |
| `docs`     | 文档修改                 | `docs: 更新 README`        |
| `style`    | 代码格式（不影响逻辑）   | `style: 统一缩进为 2 空格` |
| `refactor` | 重构（不增功能不改 Bug） | `refactor: 拆分工具函数`   |
| `perf`     | 性能优化                 | `perf: 优化列表渲染`       |
| `test`     | 测试相关                 | `test: 补充单元测试`       |
| `chore`    | 构建/工具/杂项           | `chore: 升级依赖版本`      |

## 4. 查看历史与撤销操作

### 4.1 查看提交历史 (`git log`)

| 命令                                                 | 详细说明                                                                              |
| :--------------------------------------------------- | :------------------------------------------------------------------------------------ |
| `git log`                                            | 显示完整的提交历史记录。                                                              |
| `git log --oneline`                                  | 每个提交压缩为一行显示（仅哈希 + 标题）。                                             |
| `git log --graph`                                    | 用 ASCII 图形展示分支的合并历史。                                                     |
| `git log -p -2`                                      | 显示最近 2 次提交的详细差异（diff）。                                                 |
| `git log --stat`                                     | 显示简要的增改行数统计。                                                              |
| `git log --pretty=oneline`                           | 将每个提交压缩到一行显示。                                                            |
| `git log --pretty=format:"%h - %an, %ar : %s"`       | 自定义格式化输出。                                                                    |
| `git log --since=2.weeks`                            | 仅显示最近两周内的提交。                                                              |
| `git log --author="nick"`                            | 仅显示指定作者的提交。                                                                |
| `git log --grep="first commit"`                      | 搜索提交信息中包含指定字符串的提交。                                                  |
| `git log -- <file>`                                  | 只显示某个文件的提交历史。                                                            |
| `git log --author="nick" --grep="first" --all-match` | 同时满足多个筛选条件（`--all-match` 表示 AND 关系）。                                 |
| `git reflog`                                         | 查看所有分支的所有操作记录，包括已被删除的 commit 和 reset 操作（用于“**后悔药**”）。 |

### 4.2 撤销与重置

| 命令                          | 详细说明                                                               |
| :---------------------------- | :--------------------------------------------------------------------- |
| `git commit --amend`          | 修改**最后一次**提交（可以修改提交信息或追加文件）。                   |
| `git reset HEAD <file>`       | 将文件从**暂存区**撤销，但保留工作目录中的修改（`git add` 的反操作）。 |
| `git restore --staged <file>` | 同上，新版 Git 推荐用法。                                              |
| `git checkout -- <file>`      | **丢弃**工作目录中对文件的修改，恢复到最近一次提交的状态。             |
| `git restore <file>`          | 同上，新版 Git 推荐用法。**此操作会丢失修改！**                        |
| `git reset --soft HEAD^`      | 撤销上一次 `commit`，但保留暂存区和工作目录的更改。                    |
| `git reset --mixed HEAD^`     | **(默认)** 撤销上一次 `commit`，保留工作目录的更改，但清空暂存区。     |
| `git reset --hard HEAD^`      | **(危险)** 彻底撤销上一次 `commit`，暂存区和工作目录都将回滚。         |

### 4.3 查看提交详情与定位代码

| 命令                              | 详细说明                                             |
| :-------------------------------- | :--------------------------------------------------- |
| `git show <commit>`               | 查看某个提交的详细信息（含完整 diff 和元数据）。     |
| `git show HEAD`                   | 查看最近一次提交的详细信息。                         |
| `git show --stat`                 | 查看最近一次提交的增删统计信息。                     |
| `git show <commit>:<file>`        | 查看某个提交中指定文件的内容。                       |
| `git diff <commit1> <commit2>`    | 比较两个提交之间的差异。                             |
| `git blame <file>`                | 逐行显示文件的修改作者和对应提交，用于追溯代码来源。 |
| `git blame -L 10,20 <file>`       | 只查看文件第 10 到 20 行的修改信息。                 |
| `git shortlog -sn`                | 按作者统计提交次数（用于统计贡献量）。               |
| `git log --graph --all --oneline` | 用图形方式查看所有分支的历史（推荐配合别名使用）。   |

### 4.4 撤销提交 (`git revert`)

`reset` 会改写历史，适合**尚未推送**的提交；`revert` 会生成一个“**反向提交**”，**不改写历史**，是公共分支上安全撤销的首选。

| 命令                              | 详细说明                                                   |
| :-------------------------------- | :--------------------------------------------------------- |
| `git revert <commit>`             | 撤销指定提交的改动，生成一个新的反向提交。                 |
| `git revert <commit> --no-commit` | 撤销改动但暂不提交，方便一次性撤销多个提交后再统一提交。   |
| `git revert HEAD`                 | 撤销最近一次提交。                                         |
| `git revert -m 1 <merge-commit>`  | 撤销一次合并提交（需指定保留哪一边，`1` 通常表示主分支）。 |

## 5. 远程仓库操作

| 命令                                                            | 详细说明                                                             |
| :-------------------------------------------------------------- | :------------------------------------------------------------------- |
| `git remote -v`                                                 | 查看已配置的远程仓库及其 URL。                                       |
| `git remote add <name> <url>`                                   | 添加一个新的远程仓库。                                               |
| `git remote show <name>`                                        | 查看指定远程仓库的详细信息。                                         |
| `git remote rename <old> <new>`                                 | 重命名远程仓库。                                                     |
| `git remote rm <name>`                                          | 删除指定的远程仓库。                                                 |
| `git remote prune <name>`                                       | 清理本地已失效的远程分支引用。                                       |
| `git fetch <remote> <branch>`                                   | 从远程仓库抓取更新，但**不**自动合并到本地分支。                     |
| `git fetch --prune`                                             | 抓取远程更新并清理已删除的远程分支。                                 |
| `git pull <remote> <branch>`                                    | 从远程仓库抓取更新并**自动合并**到当前本地分支 (`fetch` + `merge`)。 |
| `git push <remote> <branch>`                                    | 将本地分支的提交推送到远程仓库。                                     |
| `git push origin --delete <branch>`                             | 删除一个远程分支。                                                   |
| `git fetch --all && git reset --hard origin/master && git pull` | **(危险)** 强制用远程分支覆盖本地分支。                              |

### 5.1 推送与远程补充

| 命令                              | 详细说明                                                          |
| :-------------------------------- | :---------------------------------------------------------------- |
| `git push -u <remote> <branch>`   | 推送分支并设置上游跟踪（之后在该分支只需运行 `git push`）。       |
| `git push --all`                  | 推送所有本地分支到远程仓库。                                      |
| `git push --tags`                 | 推送所有本地标签到远程仓库。                                      |
| `git push --force`                | **(危险)** 强制推送，会覆盖远程历史（仅在确认无误时使用）。       |
| `git push --force-with-lease`     | **(推荐)** 更安全的强制推送，仅当远程分支没有被他人更新时才覆盖。 |
| `git push origin :<branch>`       | 删除远程分支（push 一个空分支的写法）。                           |
| `git ls-remote <remote>`          | 列出远程仓库的所有引用（分支、标签）。                            |
| `git remote get-url <name>`       | 查看某个远程仓库的 URL。                                          |
| `git remote set-url <name> <url>` | 修改某个远程仓库的 URL。                                          |

## 6. 分支管理

### 6.1 本地分支

| 命令                     | 详细说明                                 |
| :----------------------- | :--------------------------------------- |
| `git branch <name>`      | 创建一个新分支。                         |
| `git branch`             | 列出所有本地分支。                       |
| `git branch -r`          | 列出所有远程分支。                       |
| `git branch -a`          | 列出所有本地和远程分支。                 |
| `git branch -v`          | 查看各分支的最后一个提交信息。           |
| `git checkout <name>`    | 切换到指定分支。                         |
| `git checkout -b <name>` | 创建并立即切换到新分支。                 |
| `git branch -d <name>`   | 删除一个**已合并**的分支。               |
| `git branch -D <name>`   | **强制**删除一个分支（无论是否已合并）。 |
| `git branch --merged`    | 查看哪些分支已被合并到当前分支。         |
| `git branch --no-merged` | 查看哪些分支尚未被合并到当前分支。       |

### 6.2 跟踪分支

| 命令                                            | 详细说明                                              |
| :---------------------------------------------- | :---------------------------------------------------- |
| `git checkout --track origin/serverfix`         | 创建并跟踪一个远程分支（本地分支名与远程同名）。      |
| `git checkout -b sf origin/serverfix`           | 创建本地分支 `sf` 并跟踪远程分支 `origin/serverfix`。 |
| `git branch -u origin/serverfix`                | 为当前分支设置上游（跟踪）分支。                      |
| `git branch --set-upstream-to=origin/serverfix` | 同上。                                                |
| `git branch -vv`                                | 查看本地分支与所跟踪的远程分支的关联状态。            |

### 6.3 变基 (`rebase`)

| 命令                                             | 详细说明                                                               |
| :----------------------------------------------- | :--------------------------------------------------------------------- |
| `git rebase <basebranch>`                        | 将当前分支的提交“**变基**”到 `<basebranch>` 的顶端，使历史记录更线性。 |
| `git rebase <base> <topic>`                      | 将 `<topic>` 分支变基到 `<base>` 分支上。                              |
| `git rebase --onto <newbase> <oldbase> <branch>` | 将 `<branch>` 中基于 `<oldbase>` 的提交，重新应用到 `<newbase>` 上。   |

### 6.4 合并 (`merge`)

| 命令                           | 详细说明                                                           |
| :----------------------------- | :----------------------------------------------------------------- |
| `git merge <branch>`           | 将 `<branch>` 合并到当前分支。                                     |
| `git merge --no-ff <branch>`   | 强制生成一个合并提交（不做快进合并），保留分支合并的历史痕迹。     |
| `git merge --ff-only <branch>` | 仅在可以“**快进合并**”时才合并，否则直接报错（保持线性历史）。     |
| `git merge --squash <branch>`  | 将目标分支的所有改动合并到工作目录与暂存区，但**不生成合并提交**。 |
| `git merge --abort`            | 中止一次正在进行且存在冲突的合并。                                 |

**快进合并（Fast-forward） vs 三方合并（Three-way Merge）**

- **快进合并**：当被合并分支就是当前分支的直接后继时，Git 只需把指针向前移动，历史保持线性。
- **三方合并**：当两个分支各自都有新提交时，Git 会基于“共同祖先 + 双方”生成一个合并提交。

### 6.5 精选提交 (`cherry-pick`) 与切换 (`switch`)

| 命令                         | 详细说明                                                               |
| :--------------------------- | :--------------------------------------------------------------------- |
| `git cherry-pick <commit>`   | 将某个提交的改动“**复制**”到当前分支（常用于把单个修复合入多个分支）。 |
| `git cherry-pick <a>..<b>`   | 依次应用从 `<a>`（不含）到 `<b>`（含）范围内的提交。                   |
| `git cherry-pick --continue` | 解决冲突后继续 cherry-pick 操作。                                      |
| `git cherry-pick --abort`    | 放弃本次 cherry-pick 操作。                                            |
| `git switch <branch>`        | 切换到指定分支（Git 2.23+ 推荐，职责更单一）。                         |
| `git switch -c <branch>`     | 创建并切换到新分支（等价于 `git checkout -b`）。                       |
| `git switch -`               | 切换回上一个分支。                                                     |

### 6.6 交互式变基 (`rebase -i`)

交互式变基可以在改写历史时**合并、拆分、修改、重排或丢弃**提交，是整理提交历史（如 squash）的利器。

| 命令                     | 详细说明                                 |
| :----------------------- | :--------------------------------------- |
| `git rebase -i HEAD~n`   | 交互式变基最近 `n` 个提交。              |
| `git rebase -i <commit>` | 交互式变基到指定提交之后（不含该提交）。 |
| `git rebase --continue`  | 解决冲突后继续变基。                     |
| `git rebase --skip`      | 跳过当前冲突的提交，继续变基。           |
| `git rebase --abort`     | 放弃变基，回到变基之前的状态。           |

变基过程中常见的操作命令：`pick`（保留提交）、`reword`（修改提交信息）、`squash`（合并到上一个提交）、`fixup`（合并且丢弃信息）、`edit`（暂停以便修改）、`drop`（丢弃提交）。

> **注意**：不要对**已经推送**到公共分支的提交做 `rebase`，这会改写历史，导致他人仓库混乱；公共分支撤销请使用 `git revert`。

## 7. 标签管理 (`tag`)

| 命令                            | 详细说明                                   |
| :------------------------------ | :----------------------------------------- |
| `git tag`                       | 列出所有标签。                             |
| `git tag -n`                    | 列出标签并显示附注信息。                   |
| `git tag -l 'v1.4.2.*'`         | 使用通配符搜索标签。                       |
| `git tag -a v1.4 -m "message"`  | 创建一个带附注的标签（推荐）。             |
| `git tag -s v1.5 -m "message"`  | 创建一个 GPG 签名的标签。                  |
| `git tag -v <tag-name>`         | 验证一个 GPG 签名标签。                    |
| `git show <tag-name>`           | 查看标签信息和对应的提交信息。             |
| `git tag -a v1.2 <commit-hash>` | 对过去的某个提交追加标签。                 |
| `git describe`                  | 基于最近的标签生成一个人类可读的版本描述。 |
| `git push origin <tag-name>`    | 将指定标签推送到远程仓库。                 |
| `git push origin --tags`        | 将所有本地新增的标签一次性推送到远程仓库。 |

### 7.1 标签补充

| 命令                                    | 详细说明                                     |
| :-------------------------------------- | :------------------------------------------- |
| `git tag -d <tag-name>`                 | 删除本地标签。                               |
| `git push origin :refs/tags/<tag-name>` | 删除远程标签。                               |
| `git push origin --delete <tag-name>`   | 删除远程标签（更直观的写法）。               |
| `git checkout <tag-name>`               | 切换到某个标签对应的版本（进入分离头状态）。 |

## 8. 高级工具

### 8.1 贮藏 (`stash`)

| 命令                                    | 详细说明                                             |
| :-------------------------------------- | :--------------------------------------------------- |
| `git stash`                             | 将工作目录中未提交的修改（已跟踪文件）临时保存起来。 |
| `git stash save "message"`              | 贮藏并附加说明信息。                                 |
| `git stash list`                        | 查看所有贮藏记录。                                   |
| `git stash show -p stash@{0}`           | 查看某个贮藏的详细改动。                             |
| `git stash apply stash@{2}`             | 应用指定的贮藏，但**不**从列表中移除。               |
| `git stash pop`                         | 应用最近的贮藏，并从列表中**移除**。                 |
| `git stash drop stash@{2}`              | 丢弃指定的贮藏。                                     |
| `git stash clear`                       | 清空所有贮藏记录。                                   |
| `git stash -u` 或 `--include-untracked` | 贮藏时同时包含未跟踪的文件。                         |
| `git stash -a` 或 `--all`               | 贮藏时同时包含所有文件（包括忽略的文件）。           |
| `git stash branch <new-branch>`         | 基于指定的贮藏创建一个新分支。                       |

### 8.2 清理 (`clean`)

| 命令              | 详细说明                                          |
| :---------------- | :------------------------------------------------ |
| `git clean -n`    | **演习**：显示将要被移除的未跟踪文件。            |
| `git clean -f`    | **(危险)** 强制移除工作目录中所有未跟踪的文件。   |
| `git clean -f -d` | **(危险)** 同时移除未跟踪的文件和空目录。         |
| `git clean -x`    | **(危险)** 同时移除未跟踪文件与**被忽略**的文件。 |

### 8.3 改写历史 (`filter-branch` / `filter-repo`)

| 命令                                                         | 详细说明                                                  |
| :----------------------------------------------------------- | :-------------------------------------------------------- |
| `git filter-branch --tree-filter 'cmd'`                      | **(已过时)** 对每个提交执行指定命令来改写历史。           |
| `git filter-repo`                                            | **(推荐)** 新一代工具，用于批量改写历史，更安全、更快速。 |
| `git filter-branch --tree-filter 'rm -f passwords.txt' HEAD` | 示例：从所有提交中移除 `passwords.txt` 文件。             |

### 8.4 其他

| 命令         | 详细说明                                                                     |
| :----------- | :--------------------------------------------------------------------------- |
| `.gitignore` | 文件，用于指定 Git 应该忽略的文件或目录模式（如 `*.log`, `/node_modules`）。 |

### 8.5 二分查找定位问题 (`bisect`)

当某个 Bug 在大量提交中被引入、又不知道具体是哪一次提交时，`git bisect` 可以通过二分法快速定位。

| 命令                       | 详细说明                     |
| :------------------------- | :--------------------------- |
| `git bisect start`         | 开始二分查找。               |
| `git bisect bad`           | 标记当前版本为“**有问题**”。 |
| `git bisect good <commit>` | 标记某个版本为“**正常**”。   |
| `git bisect reset`         | 结束二分查找，回到起始状态。 |

### 8.6 工作树 (`worktree`)

允许同一仓库**同时检出多个分支到不同目录**，适合在开发时临时处理其他分支（如紧急修复）而无需打断当前工作。

| 命令                               | 详细说明                         |
| :--------------------------------- | :------------------------------- |
| `git worktree add <path> <branch>` | 在指定路径检出一个分支的工作树。 |
| `git worktree list`                | 列出所有工作树。                 |
| `git worktree remove <path>`       | 移除一个工作树。                 |

### 8.7 子模块 (`submodule`)

用于在一个仓库中嵌套另一个独立的 Git 仓库（如共享组件库）。

| 命令                                      | 详细说明                               |
| :---------------------------------------- | :------------------------------------- |
| `git submodule add <url> <path>`          | 添加一个子模块。                       |
| `git submodule update --init --recursive` | 初始化并更新所有子模块（克隆后常用）。 |
| `git submodule update --remote`           | 更新子模块到其远程最新提交。           |

### 8.8 搜索与其他工具

| 命令                                          | 详细说明                                               |
| :-------------------------------------------- | :----------------------------------------------------- |
| `git grep <pattern>`                          | 在**已跟踪**的文件中搜索指定内容（比系统 grep 更快）。 |
| `git grep -n <pattern>`                       | 搜索并显示行号。                                       |
| `git ls-files`                                | 列出所有已被跟踪的文件。                               |
| `git archive --format=zip HEAD -o <name>.zip` | 将当前版本打包为 zip 文件（不包含 `.git` 目录）。      |
| `git fsck`                                    | 检查仓库的完整性和连通性，可找回“丢失”的对象。         |
| `git fsck --lost-found`                       | 找回悬空（dangling）的 commit 对象。                   |
| `git gc`                                      | 执行垃圾回收，压缩仓库，优化性能。                     |

### 8.9 Git 钩子（Hooks）

Git 钩子是存放在 `.git/hooks/` 目录下的脚本，可在特定 Git 事件发生时自动执行（如提交前检查、提交后通知）。

| 钩子         | 触发时机               | 常见用途                 |
| :----------- | :--------------------- | :----------------------- |
| `pre-commit` | 执行 `git commit` 之前 | 代码格式检查、单元测试   |
| `commit-msg` | 提交信息写入之前       | 校验提交信息规范         |
| `pre-push`   | 执行 `git push` 之前   | 防止推送未通过测试的代码 |
| `post-merge` | 合并完成之后           | 提示重新安装依赖         |

> 提示：团队常使用 `husky`（前端）、`pre-commit` 等工具来管理钩子，比手动编辑 `.git/hooks/` 更易维护。
