# Git 核心概念

## 1. Git 是什么

Git 是一个**分布式版本控制系统（DVCS）**，由 Linus Torvalds 于 2005 年为 Linux 内核开发而创建，用于追踪文件变更、支持多人协作、历史回溯与并行开发。

| 特点           | 说明                                                                                       |
| :------------- | :----------------------------------------------------------------------------------------- |
| **分布式**     | 每个开发者都拥有完整的仓库副本（含全部历史），即使服务器宕机也能离线提交、查看历史。       |
| **快照存储**   | Git 把每次提交看作**整个项目的快照**，而非文件差异；未变更的文件只保存一个指针，节省空间。 |
| **本地操作**   | 绝大多数操作（提交、分支、历史查看）都在本地完成，速度快、无需网络。                       |
| **数据完整性** | 所有内容通过 SHA-1 哈希校验，任何改动都会被检测到。                                        |

> **对比集中式（如 SVN）**：集中式只有服务器存有完整历史，客户端每次操作都需联网；Git 的分布式模型更健壮、更灵活。

## 2. Git 的三个状态与四个区域

在阅读本文档前，先了解 Git 的几个基本区域，有助于理解每个命令的作用范围：

| 区域                              | 说明                                                      |
| :-------------------------------- | :-------------------------------------------------------- |
| **工作目录 (Working Directory)**  | 你正在编辑的文件夹，包含项目文件。                        |
| **暂存区 (Staging Area / Index)** | `git add` 之后的“**草稿箱**”，存放准备提交的内容。        |
| **本地仓库 (Local Repository)**   | `git commit` 之后，提交被永久保存在本地 `.git` 目录中。   |
| **远程仓库 (Remote Repository)**  | 托管在服务器（如 GitHub、GitLab）上的仓库，用于团队共享。 |

**数据流转方向：**

```markdown
工作目录 --git add--> 暂存区 --git commit--> 本地仓库 --git push--> 远程仓库
^ |
| --git fetch / git pull-- |
+--- git checkout / git restore / git merge --------------------+
```

### 2.1 三种状态

文件在 Git 中处于以下三种状态之一：

| 状态                   | 位置     | 触发命令     |
| :--------------------- | :------- | :----------- |
| **已修改 (Modified)**  | 工作目录 | 编辑文件后   |
| **已暂存 (Staged)**    | 暂存区   | `git add`    |
| **已提交 (Committed)** | 本地仓库 | `git commit` |

### 2.2 文件的生命周期

| 阶段                   | 说明                                                                    |
| :--------------------- | :---------------------------------------------------------------------- |
| **未跟踪 (Untracked)** | 新建但从未 `git add` 过的文件。                                         |
| **已跟踪 (Tracked)**   | 已被 Git 纳入版本控制的文件，进一步分为已修改、已暂存、已提交三种状态。 |
| **已修改 (Modified)**  | 对已跟踪文件做了改动但尚未暂存。                                        |
| **已暂存 (Staged)**    | 改动已通过 `git add` 进入暂存区。                                       |
| **已提交 (Committed)** | 改动已通过 `git commit` 写入本地仓库。                                  |

## 3. Git 的对象模型

Git 内部是一个「内容寻址」的文件系统，所有数据都以对象的形式存储在 `.git/objects` 目录中。主要有四类对象：

| 对象       | 说明                                                  |
| :--------- | :---------------------------------------------------- |
| **blob**   | 文件内容（不含文件名、路径等元数据）。                |
| **tree**   | 目录结构，记录文件名、权限及对应的 blob / tree 引用。 |
| **commit** | 一次提交，指向一个 tree 和父提交（parent）。          |
| **tag**    | 附注标签，指向某个 commit 并附带额外信息。            |

## 4. 分支与引用

### 4.1 分支的本质

Git 中的**分支只是一个可移动的指针**，指向某个 commit。创建分支只是在 `.git/refs/heads/` 下新建一个记录 commit 哈希的文件，开销极小，因此 Git 鼓励频繁创建和合并分支。

- 每次提交，当前分支指针会自动向前移动，指向最新的 commit。
- `main`、`master` 等只是分支的默认命名，没有特殊含义。

### 4.2 HEAD 指针

**HEAD** 是一个特殊指针，指向当前所在分支（或某个 commit）。正常情况下是 `HEAD -> 分支 -> commit`；当 `HEAD` 直接指向某个 commit 时，进入**分离头状态（Detached HEAD）**，此时新产生的提交不会被任何分支引用，切换分支后可能“**丢失**”。

### 4.3 引用 (refs)

| 引用     | 位置                 | 说明                           |
| :------- | :------------------- | :----------------------------- |
| 分支引用 | `.git/refs/heads/`   | 本地分支。                     |
| 远程引用 | `.git/refs/remotes/` | 远程分支的本地缓存。           |
| 标签引用 | `.git/refs/tags/`    | 标签。                         |
| `HEAD`   | `.git/HEAD`          | 指向当前分支或提交的特殊引用。 |

## 5. 合并与变基

- **合并（merge）**：将两个分支的历史汇合，保留双方各自的提交记录，产生一个合并提交（merge commit）。
- **变基（rebase）**：将当前分支的提交“**搬到**”另一个分支的顶端，改写提交历史，使其更线性。

## 6. 其他常用概念

| 概念                           | 说明                                                          |
| :----------------------------- | :------------------------------------------------------------ |
| **HEAD**                       | 一个指针，指向当前所在分支的最新提交。                        |
| **提交哈希 (SHA-1)**           | 每个提交的唯一标识，如 `c40e64d`。                            |
| **上游分支 (Upstream)**        | 本地分支所跟踪的远程分支，通常写作 `origin/main`。            |
| **origin**                     | `git clone` 时默认创建的远程仓库别名。                        |
| **分离头状态 (Detached HEAD)** | `HEAD` 直接指向某个提交而非分支，此时提交不会被任何分支引用。 |
