# OSI（Open Systems Interconnection，开放式系统互联）模型

OSI 模型把一次网络通信拆成七个相互独立的层级，从底层的物理硬件一直到高层的用户应用。每一层只解决一类问题，并且只与相邻的上下层交互。

**一句话理解**：**分层就是把“一条网线怎么把网页送到你眼前”这个巨型问题，切成七个各自只需回答一个小问题的黑盒——换掉任何一层的实现，其余六层都不用动。**

## 1. 为什么需要分层？

网络通信要同时解决一堆彼此毫不相干的问题：怎么把 0 和 1 变成电信号、怎么在几亿台设备里找到对方、怎么绕过拥堵的链路、怎么保证数据不丢不乱序、两个程序怎么开始和结束对话、中文怎么编码、浏览器和服务器该用什么格式说话。把它们搅在一个程序里，既无法维护，也无法替换。

分层带来的三样东西：

- **职责隔离**：每一层只依赖下层提供的服务，不关心下层怎么实现。写 HTTP 的人不需要懂光纤。
- **独立演进**：Wi-Fi 换成 5G，HTTP 一行都不用改；HTTP/1.1 换成 HTTP/3，网线也不用换。
- **可定位的故障**：出问题时可以自下而上逐层验证，而不是对着一整个黑盒猜。

代价也很真实：每层都要加自己的头部（额外开销）；有些层会“**越界**”破坏分层假设，比如 NAT 让 IP 地址不再端到端唯一，TLS 的层次归属至今有争议。

## 2. 七层总览

[width(11,13,36,27,13)]

| 层号   | 数据单位 | 一句话职责                                     | 典型协议                             | 代表设备       |
| :----- | :------- | :--------------------------------------------- | :----------------------------------- | :------------- |
| 应用层 | 数据     | 直接为应用程序提供网络服务                     | HTTP、DNS、SSH、SMTP、WebSocket      | 网关、代理     |
| 表示层 | 数据     | 编码、加密、压缩，让两端“**说同一种语言**”     | TLS/SSL、JPEG、UTF-8、JSON、Protobuf | ——             |
| 会话层 | 数据     | 建立、管理、终止一次通信会话                   | RPC、NetBIOS、SMB、Socket            | ——             |
| 传输层 | 数据段   | 端到端（进程到进程）传输，负责可靠性与端口寻址 | TCP、UDP、QUIC                       | 四层负载均衡   |
| 网络层 | 数据包   | 跨网络路由与逻辑寻址（IP 地址）                | IP、ICMP、ARP、OSPF、BGP             | 路由器         |
| 链路层 | 帧       | 局域网内相邻节点间的可靠传输与物理寻址         | 以太网、Wi-Fi (802.11)、PPP、VLAN    | 交换机、网卡   |
| 物理层 | 比特     | 把 0 和 1 变成物理介质上的信号                 | 双绞线、光纤、无线电（RJ45、Cat6）   | 集线器、中继器 |

**从下往上看更有条理**：物理层->链路层解决“**这台机器和隔壁那台机器怎么通**”，网络层解决“**怎么跨越无数个网络找到对方**”，传输层解决“**找到对方机器后，交给它上面的哪个程序**”，会话层->表示层->应用层才终于开始谈“**这两个程序之间说的话是什么意思**”。这也是 TCP/IP 模型干脆把 5–7 合并成一整层的原因。

## 3. 逐层详解

### 3.1 物理层 (Physical Layer)

**核心职责：负责通过物理介质传输最基础的比特流（0 和 1）。**

- **功能描述：** 物理层是 OSI 模型的最底层，也是唯一涉及真实物理连接的层。它定义了网络通信的硬件标准，包括线缆的类型（如网线、光纤）、接头的物理形状、引脚的功能，以及传输数据所需的电压电平、无线电频率和传输速率等。
- **关键概念：** 双绞线（Cat5e 千兆、Cat6 万兆）、光纤（单模走远距离、多模走机房内）、无线（无线电波）；以及“**信号会衰减、会受干扰**”这个所有上层的错误检测机制都要面对的事实。
- **数据单位：** 比特 (Bit)
- **相关设备：** 网线（双绞线、同轴电缆）、光纤、网卡接口、集线器 (Hub)、中继器、调制解调器 (Modem)。
- **形象比喻：** 就像是运送包裹的交通工具和道路（汽车、火车、公路等）。

### 3.2 数据链路层 (Data Link Layer)

**核心职责：在局域网（LAN）内的相邻节点之间建立可靠的连接，并处理物理寻址。**

- **功能描述：** 物理层只负责传输 0 和 1，难免会发生错误。数据链路层将这些比特组装成有意义的“帧（Frame）”，并在帧中加入发送方和接收方的物理地址（MAC 地址）。它还负责错误检测（确保数据在传输过程中没有损坏）和流量控制。通常分为两个子层：逻辑链路控制（LLC）和介质访问控制（MAC）。
- **关键概念：** MAC 地址 48 位、全球唯一、烧在网卡上；一个帧 = 帧头（源/目的 MAC、类型）+ 载荷 + 帧尾（FCS 校验和）；交换机靠**自学习**记住“**哪个 MAC 在哪个口**”，因此只在必要时转发，而不是像集线器那样无脑广播。
- **数据单位：** 帧 (Frame)
- **常见协议：** 以太网 (Ethernet)、Wi-Fi (IEEE 802.11)、PPP；VLAN（802.1Q）也定义在这一层，用一个标签把一台交换机逻辑上切成多台。
- **相关设备：** 交换机 (Switch)、网桥 (Bridge)、网卡 (NIC)。

### 3.3 网络层 (Network Layer)

**核心职责：负责不同网络之间的路由选择和逻辑寻址（IP 地址）。**

- **功能描述：** 如果说数据链路层负责局域网内的通信，那么网络层就负责将数据从一个网络发送到另一个网络。它将数据封装成“**数据包（Packet）**”，并使用逻辑地址（即 IP 地址）来标识发送方和最终目的地。网络层最重要的功能是“**路由**”，即决定数据包到达目的地应该走哪条最佳路径。
- **关键概念：** 逻辑地址（IP）与物理地址（MAC）的分离，是“**跨网络**”得以实现的前提——MAC 只在当前局域网内有意义，一出网关就得换；TTL 防止数据包在网络里永久打转；数据包过大时在这一层分片。
- **数据单位：** 数据包 (Packet)
- **常见协议：** IP (IPv4, IPv6)、ICMP (如 ping 命令)、IPsec、OSPF、BGP。ARP 的作用是“**用 IP 查 MAC**”，严格说它跨在 2、3 层之间，教材里通常归到链路层。
- **相关设备：** 路由器 (Router)、三层交换机。

### 3.4 传输层 (Transport Layer)

**核心职责：提供端到端（主机到主机）的可靠或不可靠的数据传输，并处理分段与重组。**

- **功能描述：** 传输层从会话层接收数据，将其分割成更小的“**数据段（Segment）**”，然后交给网络层发送。到达接收端后，传输层负责将这些数据段按正确的顺序重组。它还负责流量控制和差错恢复，确保数据完整无误地送达。通过端口号，传输层能区分同一台计算机上运行的不同网络应用程序。
- **关键概念：** 端口号是 16 位整数（0–65535），IP 定位到**机器**，端口定位到**机器上的进程**——“**IP + 端口**”才是完整的通信终点；TCP 头部 20–60 字节，UDP 头部只有 8 字节，这个差距就是“**可靠**”的代价。
- **数据单位：** 数据段 (Segment) 或 数据报 (Datagram)
- **常见协议：** TCP（面向连接，三次握手、重传、有序、拥塞控制）、UDP（无连接，快但不可靠）、QUIC（跑在 UDP 之上的新一代传输协议，HTTP/3 的底座）。

### 3.5 会话层 (Session Layer)

**核心职责：建立、管理和终止两台设备应用程序之间的通信会话。**

- **功能描述：** 就像打电话一样，会话层负责“**拨通**”和“**挂断**”。它管理两个应用程序何时开始通信，谁在发送数据，发送多久，以及何时结束。如果网络中断，会话层还提供检查点机制，允许数据从断点处恢复传输，而不需要从头开始。
- **关键概念：** 这是七层里最“**虚**”的一层——现实中几乎没有独立的会话层实现，它的职责被 Socket API、RPC 框架和应用协议各自认领了一部分。“**检查点**”的思想活了下来，也就是今天下载器的断点续传。
- **数据单位：** 数据 (Data)
- **常见协议：** NFS、SMB、RPC、NetBIOS。

### 3.6 表示层 (Presentation Layer)

**核心职责：处理数据的格式、加密和解密、压缩和解压缩。**

- **功能描述：** 表示层是网络的“**翻译官**”。不同的计算机系统可能使用不同的数据表示方式。表示层确保发送方发送的数据能够被接收方理解。它负责将应用层的数据转换为适合网络传输的通用格式，并在接收端将其转换回应用层能理解的格式。常见的数据加密（如 SSL/TLS）和数据压缩通常也在这一层处理。
- **关键概念：** 字符编码（UTF-8 统一天下之前，中文乱码就是这一层的锅）、序列化格式（JSON / Protobuf）、压缩（gzip / brotli）。**TLS 的归属需要打个补丁**：教材把它放在表示层，但它既做加密（表示层的活）又管握手和会话状态（会话层的活），在真实的 TCP/IP 栈里它位于传输层之上、应用层之下，工程上常叫它“5.5 层”。
- **数据单位：** 数据 (Data)
- **常见格式/协议：** JPEG、MPEG、ASCII、JSON、SSL/TLS。

### 3.7 应用层 (Application Layer)

**核心职责：直接为用户的软件应用程序提供网络服务。**

- **功能描述：** 应用层是最靠近用户的一层，它是用户和网络之间交互的接口。你需要注意的是，应用层**不是**指软件本身（比如 Chrome 浏览器或 Outlook），而是指这些软件用来在网络上通信的协议。当我们想要浏览网页、发送电子邮件或传输文件时，都是由应用层的协议来处理请求并准备数据的。
- **关键概念：** 前端日常打交道的一切几乎都在这一层：HTTP/1.1、HTTP/2、HTTP/3、WebSocket、DNS。它们的关系很直观——DNS 负责“**找到门牌号**”，HTTP 负责“**敲门说什么话**”，WebSocket 负责“**门开着一直聊**”。
- **数据单位：** 数据 (Data)
- **常见协议：** HTTP/HTTPS（网页浏览）、FTP（文件传输）、SMTP/POP3/IMAP（电子邮件）、DNS（域名解析）、Telnet、SSH。

## 4. 数据封装与解封装

同一份数据，在每一层都有一个不同的名字，因为每往下一层，它就被**加了一层头部**（封装，Encapsulation）：

```markdown
应用层 [ HTTP 请求报文 ] ← 报文 Message
传输层 [ TCP 头 | HTTP 报文 ] ← 数据段 Segment
网络层 [ IP 头 | TCP 头 | HTTP 报文 ] ← 数据包 Packet
链路层 [ 帧头 | IP 头 | TCP 头 | HTTP 报文 | 帧尾 ] ← 帧 Frame
物理层 101101001110... ← 比特 Bit
```

发送方自上而下逐层**加头**，接收方自下而上逐层**拆头**（解封装），每一层只看自己关心的那部分头部，然后把载荷交给上一层。这个“**只拆自己那层、剩下的原样上交**”的规矩，就是分层能成立的机械保证：

- 网卡只认 MAC，拆完帧头就把整个 IP 包丢给操作系统。
- 操作系统只认 IP，拆完 IP 头就按“**协议**”字段把载荷交给 TCP 或 UDP。
- 内核只认端口，按端口把数据交给对应的进程（这就是 `TCP 80` 和 `TCP 443` 会被监听的原因）。
- 最后，HTTP 解析器才看到那段真正有意义的 `GET /index.html`。

这也解释了一个常见现象：**同一根网线里同时跑着网页、视频和游戏，互不干扰**——它们在传输层靠端口被分给了不同的进程。这个过程叫**分用 (Demultiplexing)**。

## 5. OSI 七层 vs TCP/IP 四层

OSI 是“**先定标准、再写实现**”的理论模型；TCP/IP 是“**先有实现、再总结成模型**”的事实标准。两者的对应关系：

[width(27,17,56)]

| OSI 七层                 | TCP/IP 四层 | 说明                                                    |
| :----------------------- | :---------- | :------------------------------------------------------ |
| 应用层 / 表示层 / 会话层 | 应用层      | 这三层的边界在实现里模糊，TCP/IP 干脆合成一层           |
| 传输层                   | 传输层      | 完全对应，就是 TCP / UDP                                |
| 网络层                   | 网际层      | 完全对应，核心是 IP                                     |
| 数据链路层 / 物理层      | 网络接口层  | TCP/IP 不规定这两层的细节，交给以太网、Wi-Fi 等各自实现 |

## 6. 同层设备对比

[width(23,13,18,28,18)]

| 设备            | 工作层 | 寻址方式   | 广播域 / 冲突域                | 典型用途                  |
| :-------------- | :----- | :--------- | :----------------------------- | :------------------------ |
| 集线器 (Hub)    | L1     | 不认识地址 | 所有口同一个冲突域             | 早已淘汰，只出现在教材里  |
| 交换机 (Switch) | L2     | MAC 地址   | 每个口一个冲突域、同属一广播域 | 局域网内组网              |
| 路由器 (Router) | L3     | IP 地址    | 天然隔离广播域                 | 连接不同网段 / 接入互联网 |
| 三层交换机      | L3     | IP + MAC   | 隔离广播域（用 VLAN）          | 机房内 VLAN 间线速转发    |

一句话概括：**集线器傻广播，交换机认 MAC，路由器认 IP**。集线器把收到的每一个比特从所有口复制出去，交换机只在目的端口转发，路由器还会顺手把“**这一个网络**”和“**那一个网络**”隔开。

## 7. 分层在实战里怎么用

分层最实际的用途是排障：**自下而上验证，一旦某一层通了，就不用再怀疑它下面所有层**。

```bash
# L1 / L2：网卡是否正常工作、有没有拿到地址
ip addr show          # macOS: ifconfig

# L3：到目标 IP 通不通（走 ICMP，只验证网络层）
ping 1.1.1.1

# L3：路径上每一跳是谁、在哪一跳断了
traceroute 1.1.1.1

# L4：目标机器的端口开没开（注意这里绕过 DNS，直接用 IP）
nc -vz 93.184.216.34 443

# L7：应用层协议是否按预期工作
curl -v https://example.com
```

前端遇到报错时，先判断它属于哪一层，能省下大量瞎猜的时间：

- **DNS 解析失败**（`ERR_NAME_NOT_RESOLVED`）→ 应用层的域名解析，还没轮到建立连接。
- **连接超时 / 拒绝**（`ERR_CONNECTION_TIMED_OUT`、`ECONNREFUSED`）→ L3/L4：目标不可达，或端口没人监听。
- **证书错误**（`ERR_CERT_DATE_INVALID`）→ L5/L6：TLS 层，跟你的业务代码无关。
- **CORS 报错** → L7：请求其实已经成功往返了，是浏览器在按同源策略拦下响应。
- **404 / 500** → L7：网络全通，是服务端逻辑或路由的问题。

## 8. 常见问题 (FAQ) 与面试题

### 8.1 七层的名字怎么记？

从下往上：**物、数、网、传、会、表、应**（物理、数据链路、网络、传输、会话、表示、应用）。记住顺序比记住定义重要——排障和面试里真正用到的都是“**这个属于第几层**”。

### 8.2 现实中用的是 TCP/IP，为什么还要学 OSI？

OSI 是**参考模型**，它的价值不在实现，而在提供一套**通用词汇**：说“这是 L7 的问题”所有人都懂。它由 ISO 先定标准、后写实现，过程漫长且标准过于复杂，最终被先跑起来的 TCP/IP 取代。今天没人照着 OSI 实现协议栈，但所有人都在用它的分层语言描述问题。

### 8.3 交换机、路由器、集线器有什么区别？

一句话：**集线器傻广播，交换机认 MAC，路由器认 IP**，而三层交换机等于把路由器的路由能力用硬件线速做出来，专门用于机房内部。

### 8.4 TLS 到底算第几层？

教材说表示层，现实中它夹在传输层和应用层之间（常被戏称 5.5 层）：加密是表示层的职责，握手和会话管理又像会话层。**实用结论**：面试答“**位于传输层之上、应用层之下，兼具会话层与表示层的职责**”最稳妥；另外在 HTTP/3 里 TLS 1.3 被内置于 QUIC，不再是独立的一层。

### 8.5 为什么 HTTP/3 要跑在 UDP 上？

因为 TCP 已经改不动了：TCP 的重传是“**整条连接有序**”，一个包丢了后面所有数据都得等着（队头阻塞）；而 TCP 头部里的很多字段早已被中间设备（防火墙、NAT）“冻结”成固定语义，想改也推不动。QUIC 于是把可靠性、加密、多路复用全部上移到用户态的 UDP 之上，既能绕开队头阻塞，也能靠用户态快速迭代。

### 8.6 数据在每一层分别叫什么？

应用层叫**报文 (Message)**，传输层叫**数据段 (Segment)**，网络层叫**数据包 (Packet)**，链路层叫**帧 (Frame)**，物理层叫**比特 (Bit)**。

### 8.7 分层会不会带来性能损耗？

会，而且这是它的主要代价：每层加头部（一个 HTTP 包实际要多带几十字节）、每层要拆装（CPU 开销）、层与层之间还要复制数据。所以高吞吐场景会出现“**零拷贝**”“内核旁路 (DPDK)”这类技术，本质都是**在保留分层语义的前提下，绕过实际的数据复制**。

### 8.8 为什么跨域、证书这类问题总被说成“跟后端没关系”？

因为它们确实发生在不同的层：网络层和传输层负责把字节送到，TLS 层负责证明“**对面是谁**”，而同源策略是浏览器在**应用层之上**额外加的一道本地规则。理解分层，就能理解为什么“**接口明明返回 200，浏览器里却报错**”——200 是服务器给的，拦截发生在浏览器拿到响应之后。
