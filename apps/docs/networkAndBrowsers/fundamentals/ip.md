# IP 协议

## 1. 什么是 IP 协议？

**IP** (Internet Protocol，互联网协议) 是整个 TCP/IP 协议族中**最核心的协议之一**。在 OSI 模型中，它位于第三层（**网络层**），向下承接数据链路层（如以太网、Wi-Fi），向上服务于传输层（如 TCP、UDP）。

如果说 TCP 是负责把包裹打包并保证完好无损的“**快递总管**”，那么 **IP 协议就是整个“国家邮政系统”及其内部的“分拣转运规则”**。它的唯一使命是：**将数据包从源主机，跨越多个网络（路由器），尽力送达到目标主机。**

**一句话理解**：**IP 只负责“把包送到哪台机器”，既不保证送到，也不关心包里面装的是什么。**

## 2. IP 协议的核心特征

IP 协议的设计理念非常纯粹，可以用三个词概括：

- **无连接 (Connectionless)：** 发送数据之前，源主机和目标主机之间不需要建立任何连接。每个 IP 数据包（也叫数据报）都是独立的，它们可能走不同的物理路径到达目的地。
- **不可靠 (Unreliable)：** IP 协议**不保证**数据包一定能送达。如果途中遇到路由器拥堵、线路故障或数据校验错误，IP 协议会直接丢弃该数据包，且**不会**通知发送方。可靠性（如重传机制）完全交由上层的 TCP 协议来保障。
- **尽力而为 (Best-Effort Delivery)：** 虽然不可靠，但 IP 协议绝不偷懒。它会尽最大努力把数据包传输出去，不到万不得已绝不丢弃。

这三条加起来就是**无状态 (Stateless)**：路由器不记录“**刚才那个包发去哪了**”，每个包都被独立判断、独立转发。这也是 IP 能扛住全球流量的根本原因——**路由器不需要为任何一条连接保存状态**，坏了换一台、流量涨了加一台，都只是加机器而已。代价是上层的 TCP 必须在两端自己维护连接状态、序号和重传计时器。

## 3. IP 地址体系 (IPv4 与 IPv6)

要实现全网通信，必须给网络上的每一个设备分配一个唯一的“**家庭住址**”，这就是 IP 地址。

### 3.1 IPv4 (目前的绝对主流)

- **格式：** 由 32 位二进制数组成，通常写成 4 段十进制数字（点分十进制），例如：`192.168.1.1`。
- **容量危机：** 32 位地址理论上最多只能提供约 43 亿个地址。随着移动互联网和物联网的爆发，IPv4 地址早在 2011 年就已分配殆尽。（目前主要靠 NAT 技术——让一个局域网共用一个公网 IP 来续命）。

### 3.2 IPv6 (未来的必然趋势)

- **格式：** 由 128 位二进制数组成，通常写成 8 段十六进制数字，例如：`2001:0db8:85a3:0000:0000:8a2e:0370:7334`。
- **容量恐怖：** 它的地址数量多到“**可以给地球上的每一粒沙子都分配一个 IP 地址**”，彻底解决了地址枯竭问题，并自带更高的安全性（内置 IPsec）。
- **书写缩写规则：** 每一段开头的 `0` 可以省略（`0db8` → `db8`）；连续的一段或多段 `0000` 可以用一次 `::` 代替，但**整个地址里 `::` 只能出现一次**。上面的地址可以缩写成 `2001:db8:85a3::8a2e:370:7334`。
- **常见的几类 IPv6 地址：** `::1` 是本机回环（对应 IPv4 的 `127.0.0.1`）；`fe80::/10` 开头的**链路本地地址**，相当于 IPv4 里那个自动生成、只在局域网内有效的小地址，邻居发现协议靠它工作；`2001:` 开头的才是可以全球路由的公网地址。

### 3.3 私有地址、公有地址与 NAT

- **公有 IP：** 全球唯一，可以直接在互联网上被访问。
- **私有 IP：** 用于家庭、公司内部局域网。它们在互联网上不可见，任何人都不会把它们当作公网目的地路由。三段保留地址是：
  - `10.0.0.0/8`（`10.x.x.x`，大型内网）
  - `172.16.0.0/12`（`172.16.x.x` – `172.31.x.x`）
  - `192.168.0.0/16`（`192.168.x.x`，家用路由器最常见）
- **NAT (网络地址转换)：** 你的电脑只有一个 `192.168.1.5`，但访问外网时源地址会被家里的路由器改写成它自己的公网 IP，并用一张“**端口映射表**”记住“**这个连接原来是家里哪台机器的**”。回来时再反向翻译一次。**代价**：外网无法主动连内网机器（所以家里要装摄像头做端口映射），且 IP 在传输全程不再唯一——这也是分层假设被打破的典型例子。

### 3.4 子网掩码、网段与 CIDR

**IP 地址 = 网络号 + 主机号**。判断“**对方跟我在不在同一个局域网**”，靠的不是地址本身，而是**子网掩码**：

- `192.168.1.5` 配掩码 `255.255.255.0`（写作 **`192.168.1.5/24`**），意味着前 24 位是网络号：同网段的 `192.168.1.9` 直接二层可达，而 `192.168.2.9` 不在同网段，必须交给**默认网关**（通常是 `192.168.1.1`，也就是你家路由器）去转发。
- **CIDR 记法**：`/24` 表示前 24 位是网络号。主机数 = 2^(32-24) - 2 = **254 台**（全 0 的地址是网络地址、全 1 的是广播地址，都不能分给主机）。
- 常见网段对照：`/24` → 254 台（家用）、`/16` → 65534 台（大型内网）、`/8` → 千万级（如 `10.0.0.0/8`）。
- **前端视角**：CI 里的“**内网地址**”“**同网段**”判断、`vite --host` 打印的那个 `Network: http://192.168.1.5:5173/`，都是这套规则算出来的——因为它和你的设备在同一个 `/24` 里，手机才能扫到这个地址。

### 3.5 特殊地址速查

[width(24,26,50)]

| 地址                | 含义                             | 用途                                                       |
| :------------------ | :------------------------------- | :--------------------------------------------------------- |
| `127.0.0.1` / `::1` | 本机回环地址                     | 数据包不出网卡，只在本机转一圈，用于本机服务调试           |
| `0.0.0.0`           | “**本机所有网卡**”               | 服务监听时表示“**任何网卡上的请求都收**”，不是真的一个地址 |
| `169.254.x.x`       | 链路本地地址（Windows 叫 APIPA） | **没拿到 DHCP 地址时的兜底**，看到它基本等于“**网络不通**” |
| `255.255.255.255`   | 受限广播地址                     | 只发给同一局域网内的所有设备                               |
| `fe80::` 开头       | IPv6 链路本地地址                | 只在当前链路上有效，IPv6 的邻居发现全靠它                  |

## 4. IP 报文头部的核心字段

当上层的 TCP 或 UDP 数据来到网络层时，IP 协议会给它套上一个 IP 头部，打包成 IP 数据报。

- **版本号 (Version)：** 占 4 位，表明这是 IPv4 还是 IPv6。
- **首部长度 (IHL)：** 占 4 位，以 4 字节为单位记录头部有多长。IPv4 头部最短 20 字节、最长 60 字节（因为“可选项”字段长度可变），IPv6 则固定 40 字节——**固定长度让路由器处理更快，是 IPv6 简化转发流程的用心之一**。
- **总长度 (Total Length)：** 占 16 位，说明整个数据报（头部 + 数据）有多少字节。上限是 65535 字节，这也是“**一个 IP 包最大不可能超过 64KB**”的由来。
- **标识 (Identification) / 标志 (Flags) / 片偏移 (Fragment Offset)：** 这三个字段是**为分片服务的**（见第 6 节），用来标识“**这几个包原本是一个大包**”以及“**我在原包里的位置**”。
- **生存时间 (TTL, Time To Live)：** 占 8 位。这是一个**防死循环的神器**。数据包每经过一个路由器，TTL 的值就减 1。当 TTL 减为 0 时，路由器会直接丢弃该包。这防止了数据包在网络故障时永远在几个路由器之间转圈圈。
- **协议 (Protocol)：** 占 8 位，告诉目标主机的网络层，这个包裹拆开后应该交给上面的谁（如果是 `6` 代表交由 TCP 处理，如果是 `17` 代表交由 UDP 处理）。**它就是一个“交班给谁”的编号**，接收方靠它完成分用。
- **首部校验和 (Header Checksum)：** 只校验头部本身，不校验数据（数据的完整性由 TCP/UDP 的校验和负责）。每经过一跳，TTL 变了，校验和就得重算——这也是 IPv6 干脆去掉这个字段的原因。
- **源 IP 地址 (Source Address)：** 占 32 位，表明“**包裹是谁寄出的**”。
- **目的 IP 地址 (Destination Address)：** 占 32 位，表明“**包裹要寄给谁**”。

## 5. IP 路由：包裹是如何跨越全球的？

IP 协议最核心的能力就是**路由寻址（Routing）**。

当你在北京给纽约的服务器发送一个 IP 数据包时，它并不知道一条完整的直达路线。它采用的是“**接力赛（Hop-by-Hop）**”模式：

- 你的电脑检查目标 IP 发现不在同一个局域网，于是把包交给家里的路由器（默认网关）。
- 家里路由器拆开包看一下目标 IP，查一下自己的**路由表**，发现应该交给运营商的骨干路由器。
- 骨干路由器再查路由表，交给海底光缆的节点路由器...
- 就这样，数据包在途中经历十几次甚至几十次“**问路（查询路由表）和转发（跳跃 Hop）**”，最终抵达纽约的服务器。

> **核心逻辑：** 每一台路由器都不需要知道去纽约的完整路线，它只需要知道“下一步该把包扔给谁离纽约更近”即可。

**跨网段通信时，MAC 地址会一路更换**：你的电脑发出的帧，目的 MAC 是网关；网关拆掉再发时，目的 MAC 是下一跳路由器。IP 地址（寄件人/收件人）全程不变，MAC 地址（这一程的司机）每一跳都换——这正是“**逻辑地址**”与“**物理地址**”分工的意义。

## 6. 分片与 MTU

数据链路层对帧的大小有硬上限（以太网是 **1500 字节**，叫 **MTU**，最大传输单元）。一个 IP 包如果比 MTU 还大，网络层就必须把它 **分片 (Fragmentation)** 成多个小包：

- 分片用的是 IP 头部的**标识、标志、片偏移**三个字段：同一个原包的分片共享一个“**标识**”，`片偏移`记录自己在原包中的位置，`标志`里的 `DF`（Don't Fragment）位则表示“**我不许被分片**”。
- 接收方主机在网络层**重组**分片，**中间的路由器不负责重组**（否则路由器要保存状态，代价太大）。
- **只要有一个分片丢了，整个 IP 包就废了**——上层 TCP 只能重传整个段。所以分片对性能是坏事。
- 现代做法是**路径 MTU 发现 (PMTUD)**：用 `DF=1` 试探，谁过不去谁回一个 ICMP 错误，发送方据此调整包大小。这也解释了那个经典网络故障——**防火墙把 ICMP 全禁掉后，PMTUD 失灵，大包全被黑洞掉**，表现是“**小请求正常、大响应卡死**”。
- **前端视角**：HTTP 响应体大小由 TCP 分段处理，本来不需要你操心；但 `ping` 的默认 56/64 字节能通、`ping -s 2000` 不通，就是“**小包能过、大包被 MTU 卡住**”的典型自检手法。

## 7. IP 的邻居们：ARP、ICMP 与 DHCP

IP 自己只认地址，落地时还得靠三个“**帮手**”：

[width(11,21,68)]

| 协议     | 属于哪一层       | 解决的问题                                                                                      |
| :------- | :--------------- | :---------------------------------------------------------------------------------------------- |
| **ARP**  | 跨 L2/L3         | “我知道对面 IP 是 `192.168.1.1`，但这一帧该填谁的 MAC？”——用 IP 换 MAC，结果缓存在本机 ARP 表里 |
| **ICMP** | 网络层           | 报告差错与诊断：`ping` 是 Echo 请求/应答，`traceroute` 靠的是 TTL 超时报文                      |
| **DHCP** | 应用层（跑 UDP） | “**我刚插上网线，谁能给我一个 IP、掩码、网关和 DNS？**”——即插即用的地址分配                     |

它们的分工很像收快递：**DHCP 给你分一个门牌号，ARP 负责在小区里问出邻居的门牌对应哪个门，ICMP 负责告诉你“查无此人”或“超时退回”**，而 IP 才是那个真正写明收件人并决定往哪转的邮局。

## 9. 常见问题 (FAQ)

### 9.1 IP 协议既然不可靠，为什么还要用它？

**为了效率和灵活性。** 网络层的任务就是快速转发数据。如果把重传、排序等复杂逻辑都放在这一层，路由器的负担会太重，导致全网变慢。复杂的逻辑交给端点（主机）的 TCP 层去处理，实现了“**简单网络，复杂终端**”的优秀设计理念——这也正是端到端原则：**网络只提供最基础的转发，智能放在两端。**

### 9.2 IP 地址和 MAC 地址有什么区别？

- **IP 地址 (逻辑地址)**：像你的“**收货地址**”（如 某省某市某街道）。它是动态分配的，决定了你在网络中的逻辑位置，用于跨网络定位；**每跨一个网络就会变**（NAT 场景下整个局域网共用一个）。
- **MAC 地址 (物理地址)**：像你的“**身份证号**”。它是固化在网卡里的，全球唯一。它负责在**同一个局域网**内找到对应的硬件设备，**只在当前链路上有效**，出了网关就换。

一句话：**IP 负责“送到哪台机器”，MAC 负责“这一程交给谁”。**

### 9.3 什么是私有 IP 和公有 IP？

- **公有 IP**：全球唯一，可以直接在互联网上被访问。
- **私有 IP**：用于家庭、公司内部局域网（如 `192.168.x.x`）。它们在互联网上不可见。通过 **NAT** 技术，多个私有 IP 可以共享一个公有 IP 来上网。

### 9.4 什么是静态 IP 和动态 IP？

- **静态 IP**：固定不变的地址，通常给服务器使用，方便别人访问(也是域名解析里 A 记录能长期不变的前提）。
- **动态 IP**：每次上网时通过 **DHCP 协议** 临时分配的地址，资源利用率更高，适合普通家用电脑和手机。租约到期前 DHCP 会尝试续租，所以重启路由器后你的内网 IP 可能变、也可能不变。

### 9.5 如果 TTL 设得太小会怎样？

- 数据包可能还没到达目的地，就在半路因为 TTL 耗尽而被路由器丢弃。你会收到一个 **ICMP Time Exceeded** 的报错信息。
- **各系统的默认 TTL 并不相同**：Linux 及 macOS 通常是 `64`，Windows 是 `128`，部分路由器是 `255`。所以 `ping` 一个陌生的服务器时，看到 `TTL=52` 大致能推断出对方是 Linux 且路径上有十几跳——TTL 也是“**反推操作系统和跳数**”的常用手段。
- 反过来，TTL 太大并不会有害，只是万一形成环路时会多绕一会儿。

### 9.6 为什么 `ping` 通了，网页却打不开？

因为 `ping` 走的是 **ICMP**，它只证明到目标 IP 的**网络层（L3）**是通的，完全不涉及端口和应用协议。剩下的可能：目标端口没在监听、防火墙只放行了 ICMP 却拦了 443、DNS 解析到了错误的 IP、服务端返回了 500、或者证书过期（TLS 层）。**用 `curl -v` 代替 `ping` 才能看到应用层的真实情况**。

### 9.7 一个 IP 能对应多个域名吗？反过来呢？

- **一个 IP → 多个域名**：可以，而且极常见。判断“**你要访问哪个网站**”靠的是 **HTTP 请求里的 `Host` 头**（以及 HTTPS 握手里的 **SNI**），这就是**虚拟主机**：一台服务器上跑几百个站点，共用同一个 IP，全靠名字区分。
- **一个域名 → 多个 IP**：也可以。DNS 里给同一个域名配多条 A 记录就是**轮询（Round Robin）**，起到简单的负载均衡作用；CDN 更是会给不同地区的用户返回完全不同的 IP。

这也是为什么“**换个 IP 就能绕过域名封禁**”往往不好使——服务端靠 `Host` / SNI 认人，而不是靠 IP。

### 9.8 IPv4 和 IPv6 能共存吗？

能，而且现实中长期共存，三种过渡手段并行使用：

- **双栈 (Dual Stack)**：设备和网站同时配置 IPv4 与 IPv6 地址，优先走 IPv6。这是目前的主流做法。
- **隧道 (Tunneling)**：把 IPv6 包塞进 IPv4 包里穿越只支持 IPv4 的网络（6to4、Teredo）。
- **NAT64 / DNS64**：纯 IPv6 的网络访问纯 IPv4 的服务时，由网关做地址转换。
- **前端要注意的坑**：Node 服务监听 `0.0.0.0` 只收 IPv4，监听 `::` 则同时收 IPv4/IPv6（取决于系统是否开启双栈映射）；而 `localhost` 在部分环境会被优先解析成 `::1`，导致“**服务明明起来却连不上**”——把监听地址写成 `::` 或显式指定 `127.0.0.1` 都能绕开这个经典问题。
