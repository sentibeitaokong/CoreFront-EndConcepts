# 动态规划算法 (Dynamic Programming)

## 1. 动态规划核心概览

动态规划（DP）并不是某种具体的代码模板，而是一种**解决复杂问题的思维方式**。它的核心在于将一个复杂的大问题分解为相互重叠的子问题，并通过**保存已解决的子问题答案**（状态记录），避免重复计算，从而将指数级的时间复杂度降为多项式级。

### 1.1 适用动态规划的两个必要条件

[width(18,32,50)]

| 核心特征       | 详细说明                                             | 验证方法                                                                             |
| :------------- | :--------------------------------------------------- | :----------------------------------------------------------------------------------- |
| **最优子结构** | 大问题的最优解，可以由其各个子问题的最优解推导出来。 | 如果你能在不考虑之前选择的情况下，仅仅根据最后一步推导出当前状态，就满足。           |
| **重叠子问题** | 在拆解问题的过程中，相同的子问题会被反复计算多次。   | 画出递归树，如果发现有相同的节点（如斐波那契数列中的 `fib(3)` 被计算多次），就满足。 |

### 1.2 动态规划解题四步法 (核心秘籍)

- **定义状态（State）：** 定义一个数组（一维 `dp[i]` 或二维 `dp[i][j]`），并明确这个数组里的每一个元素代表什么业务含义。
- **推导状态转移方程（Transition Equation）：** 找出 `dp[i]` 是如何通过它前面的状态（如 `dp[i-1]`、`dp[i-2]`）计算出来的。这是最难也是最核心的一步。
- **初始化（Initialization）：** 确定 `dp` 数组的初始值（如 `dp[0]`、`dp[1]`），为状态转移提供起点。
- **确定遍历顺序（Traversal Order）：** 明确是应该从前向后遍历，还是从后向前，或是二维数组的特殊遍历方式。

## 2. 经典 DP 场景与 JavaScript 实现

### 2.1 爬楼梯问题 (Climbing Stairs)

**题目描述：** 假设你正在爬楼梯。需要 `n` 阶你才能到达楼顶。每次你可以爬 1 或 2 个台阶。你有多少种不同的方法可以爬到楼顶呢？

- **定义状态：** `dp[i]` 表示爬到第 `i` 阶楼梯的方法总数。
- **状态转移方程：** 到达第 `i` 阶，要么是从 `i-1` 阶跨 1 步上来，要么是从 `i-2` 阶跨 2 步上来。所以 `dp[i] = dp[i-1] + dp[i-2]`。
- **初始化：** `dp[1] = 1`（爬1阶只有1种方法），`dp[2] = 2`（爬2阶有2种方法：1+1或2）。
- **遍历顺序：** 从前向后（`i` 从 3 开始）。

```js
/**
 * 爬楼梯 - 基础 DP O(n)空间
 * @param {number} n
 * @return {number}
 */
function climbStairs(n) {
  if (n <= 2) return n

  let dp = new Array(n + 1).fill(0) // 创建 dp 数组，长度 n+1 为了让索引与楼梯数对齐
  dp[1] = 1
  dp[2] = 2

  for (let i = 3; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2] // 状态转移
  }

  return dp[n]
}
```

由于 `dp[i]` 仅仅依赖于前面的两个状态，我们其实不需要维护一个长数组，只需要两个变量滚动记录即可。

```js
/**
 * 爬楼梯 - 状态压缩 (推荐) O(1) 空间
 */
function climbStairsOptimized(n) {
  if (n <= 2) return n

  let prev2 = 1 // 相当于 dp[i-2]
  let prev1 = 2 // 相当于 dp[i-1]
  let current = 0 // 相当于 dp[i]

  for (let i = 3; i <= n; i++) {
    current = prev1 + prev2
    // 滚动更新变量，为下一次循环做准备
    prev2 = prev1
    prev1 = current
  }

  return current
}
```

### 2.2 最大子数组和 (Maximum Subarray)

**题目描述：** 给你一个整数数组 `nums` ，请你找出一个具有最大和的连续子数组（子数组最少包含一个元素），返回其最大和。例如 `[-2, 1, -3, 4, -1, 2, 1, -5, 4]` 的最大子数组是 `[4, -1, 2, 1]`，和为 `6`。

- **定义状态：** `dp[i]` 表示以 `nums[i]` **结尾** 的连续子数组的最大和。（注意：必须是以它结尾）
- **状态转移方程：** 对于 `nums[i]`，它有两个选择：要么加入前面的连续序列（`dp[i-1] + nums[i]`），要么自立门户从自己重新开始（`nums[i]`）。取两者的最大值：`dp[i] = Math.max(dp[i-1] + nums[i], nums[i])`。
- **初始化：** `dp[0] = nums[0]`。
- **遍历顺序：** 从前向后。

```js
/**
 * 最大子数组和
 * @param {number[]} nums
 * @return {number}
 */
function maxSubArray(nums) {
  if (nums.length === 0) return 0

  let dp = new Array(nums.length)
  dp[0] = nums[0]
  let maxSum = dp[0] // 记录全局最大值

  for (let i = 1; i < nums.length; i++) {
    // 如果前面的和大于 0，就加上；否则直接另起炉灶取自己
    dp[i] = Math.max(dp[i - 1] + nums[i], nums[i])

    // 随时更新全局最大值
    maxSum = Math.max(maxSum, dp[i])
  }

  return maxSum
}

// 同样可以进行状态压缩，将空间复杂度降为 O(1)：
function maxSubArrayOptimized(nums) {
  let currentMax = nums[0]
  let globalMax = nums[0]
  for (let i = 1; i < nums.length; i++) {
    currentMax = Math.max(nums[i], currentMax + nums[i])
    globalMax = Math.max(globalMax, currentMax)
  }
  return globalMax
}
```

### 2.3 零钱兑换 (Coin Change) - 二维 DP 经典题

**题目描述：** 给你一个整数数组 `coins` 表示不同面额的硬币，另给一个整数 `amount` 表示总金额。计算并返回可以凑成总金额所需的 **最少的硬币个数** 。如果没有任何一种硬币组合能组成总金额，返回 `-1`。每种硬币的数量是无限的。

- **定义状态：** `dp[i]` 表示凑成金额 `i` 所需的最少硬币数。
- **状态转移方程：** 凑成金额 `i` 的最少硬币数，等于【凑成金额 `i - coin` 的最少硬币数 + 1】（遍历所有硬币面值找最小值）。即：`dp[i] = Math.min(dp[i], dp[i - coin] + 1)`。
- **初始化：** `dp[0] = 0`（凑0元不需要硬币）。其他索引初始化为一个不可能的极大值（如 `Infinity` 或 `amount + 1`），以便在求 `Math.min` 时被覆盖。
- **遍历顺序：** 外层遍历金额（从 1 到 `amount`），内层遍历硬币面值。

```js
/**
 * 零钱兑换 (完全背包问题变种)
 * @param {number[]} coins 硬币面值数组
 * @param {number} amount 目标金额
 * @return {number}
 */
function coinChange(coins, amount) {
  // 初始化 dp 数组，默认值为 amount + 1 (相当于无穷大)
  let dp = new Array(amount + 1).fill(amount + 1)
  dp[0] = 0 // 凑 0 元需要 0 个硬币

  // 外层遍历所有金额状态
  for (let i = 1; i <= amount; i++) {
    // 内层遍历每种硬币
    for (let coin of coins) {
      // 如果当前硬币面值小于等于要凑的金额
      if (i >= coin) {
        // 状态转移：取当前记录的最少硬币数，和 (减去该硬币面值后的最少硬币数 + 1) 的较小值
        dp[i] = Math.min(dp[i], dp[i - coin] + 1)
      }
    }
  }

  // 如果 dp[amount] 还是初始值，说明凑不出来，返回 -1
  return dp[amount] === amount + 1 ? -1 : dp[amount]
}

console.log(coinChange([1, 2, 5], 11)) // 输出: 3 (11 = 5 + 5 + 1)
```

### 2.4 高频 DP 题型与建模套路

刷题时**想得出状态定义**比**会写代码**更关键。下面这张表覆盖了面试中最常见的 DP 题型，可以当作建模速查表：

[width(18,33,49)]

| 题型                   | 状态定义 `dp[i]` / `dp[i][j]`                         | 状态转移方程（核心）                                                                         |
| :--------------------- | :---------------------------------------------------- | :------------------------------------------------------------------------------------------- |
| 0-1 背包               | `dp[j]`：容量为 `j` 时的最大价值                      | 倒序遍历：`dp[j] = max(dp[j], dp[j - w] + v)`                                                |
| 完全背包               | `dp[j]`：容量为 `j` 时的最大价值                      | 正序遍历：`dp[j] = max(dp[j], dp[j - w] + v)`                                                |
| 最长递增子序列 (LIS)   | `dp[i]`：以 `nums[i]` **结尾**的最长递增子序列长度    | `dp[i] = max(dp[j]) + 1`，其中 `j < i` 且 `nums[j] < nums[i]`                                |
| 最长公共子序列 (LCS)   | `dp[i][j]`：`a` 前 `i` 个与 `b` 前 `j` 个的 LCS 长度  | 字符相等取 `dp[i-1][j-1] + 1`，否则取 `max(dp[i-1][j], dp[i][j-1])`                          |
| 编辑距离               | `dp[i][j]`：`a` 前 `i` 个变成 `b` 前 `j` 个的最少操作 | 相等取 `dp[i-1][j-1]`，否则取 `min(增, 删, 改) + 1`                                          |
| 打家劫舍               | `dp[i]`：偷到第 `i` 家的最大金额                      | `dp[i] = max(dp[i-1], dp[i-2] + nums[i])`                                                    |
| 股票买卖（可多次交易） | `dp[i][0/1]`：第 `i` 天「不持有 / 持有」时的最大利润  | 不持有取 `max(dp[i-1][0], dp[i-1][1] + price)`，持有取 `max(dp[i-1][1], dp[i-1][0] - price)` |
| 区间 DP                | `dp[i][j]`：区间 `[i, j]` 上的最优值                  | 枚举分割点 `k`：`dp[i][j] = max(dp[i][k] + dp[k+1][j] + cost)`                               |

> [!TIP]
> 判断「该用哪种背包」的口诀：物品只能取一次（0 或 1）→ **0-1 背包，一维数组倒序**；物品可以取无限次 → **完全背包，一维数组正序**。这个「正序 / 倒序」的区别，正是背包问题最高频的考点。

:::code-group

```js[0-1 背包]
/**
 * 题目描述：有 `n` 件物品和一个容量为 `W` 的背包，
 * 第 `i` 件物品重量 `w[i]`、价值 `v[i]`，每件物品最多拿一次，求能装入的最大价值。
 * 0-1 背包 - 一维滚动数组
 * @param {number} W 背包容量
 * @param {number[]} w 每件物品的重量
 * @param {number[]} v 每件物品的价值
 * @returns {number}
 */
function knapsack01(W, w, v) {
  // dp[j] 表示容量为 j 时能装下的最大价值
  const dp = new Array(W + 1).fill(0)

  // 外层遍历物品
  for (let i = 0; i < w.length; i++) {
    // 内层容量必须【倒序】，才能保证每件物品只被用一次
    for (let j = W; j >= w[i]; j--) {
      dp[j] = Math.max(dp[j], dp[j - w[i]] + v[i])
    }
  }

  return dp[W]
}

console.log(knapsack01(4, [1, 3, 4], [15, 20, 30])) // 输出: 35 (拿重量 1 和 3 的两件物品)
```

```js [最长递增子序列 LIS]
/**
 * **题目描述：** 求数组中最长严格递增子序列的长度。
 * 例如 `[10, 9, 2, 5, 3, 7, 101, 18]` 的答案是 `4`（对应 `[2, 3, 7, 101]`）。
 * 最长递增子序列 - O(n^2)
 * @param {number[]} nums
 * @returns {number}
 */
function lengthOfLIS(nums) {
  if (nums.length === 0) return 0

  // dp[i] 表示以 nums[i] 结尾的最长递增子序列长度
  const dp = new Array(nums.length).fill(1)

  for (let i = 1; i < nums.length; i++) {
    for (let j = 0; j < i; j++) {
      if (nums[j] < nums[i]) {
        dp[i] = Math.max(dp[i], dp[j] + 1)
      }
    }
  }

  return Math.max(...dp)
}
```

```js [LIS优化(贪心+二分)]
/**
 * 最长递增子序列 - O(n log n)
 * @param {number[]} nums
 * @returns {number}
 */
function lengthOfLISFast(nums) {
  // tails[k] 表示长度为 k+1 的递增子序列的「最小结尾值」
  const tails = []

  for (const num of nums) {
    let left = 0
    let right = tails.length
    // 二分查找第一个 >= num 的位置
    while (left < right) {
      const mid = (left + right) >> 1
      if (tails[mid] < num) left = mid + 1
      else right = mid
    }
    tails[left] = num // 替换或追加到末尾
  }

  return tails.length
}
```

### 2.5 空间优化：滚动数组与一维数组倒序

DP 的空间复杂度常常可以从表格压到一维，思路是「**用不到的旧状态就别存了**」。

[width(13,52,35)]

| 优化手法         | 适用条件                                        | 效果                                                 |
| :--------------- | :---------------------------------------------- | :--------------------------------------------------- |
| 滚动变量         | `dp[i]` 只依赖前 1~2 个状态（爬楼梯、打家劫舍） | 数组 → 常数个变量，$O(n)$ → $O(1)$                   |
| 滚动数组（两行） | `dp[i]` 只依赖 `dp[i-1]`（LCS、编辑距离）       | 二维表 → 两行一维数组，$O(mn)$ → $O(\min(m, n))$     |
| 一维数组 + 倒序  | 0-1 背包：每件物品只能用一次                    | `dp[j]` 读到的是「上一轮」旧值，不会重复使用当前物品 |
| 一维数组 + 正序  | 完全背包：物品可用无限次                        | 允许本轮刚更新的值再次参与转移，等价于无限次取用     |

> [!IMPORTANT]
> 「背包倒序」是理解 DP 空间优化的分水岭：一维数组里，`dp[j - w]` 的下标小于 `j`，**正序**遍历时它可能已经被**本轮**更新过，于是同一件物品被拿了多次（这正是完全背包想要的）；**倒序**遍历时它一定还是**上一轮**的值，保证物品只用一次（这正是 0-1 背包想要的）。

## 3. 常见问题深度剖析 (FAQ)

### 3.1 怎么区分一道题该用贪心算法还是动态规划？

**贪心算法**只顾眼前最优，一旦选定就不后悔，不记录状态；**动态规划**则综合考虑之前的所有状态，求全局最优。若题目说“**每种选择会影响未来的结果**”，或贪心解不是最优（如硬币面值 `[1, 3, 4]` 凑 6 元，贪心得 `4 + 1 + 1`，DP 得最优的 `3 + 3`），就必须用 DP。实战做法：先用贪心思路走一遍，找不出反例就用，一旦找到反例立刻转 DP。

### 3.2 总是找不出“**状态转移方程**”怎么办？

找不出来往往是因为没有看透“**前后状态的联系**”。用**回退法**：假设你已经到达最终状态 `n`，问自己“**我是怎么来到这里的**”，通常只有几种明确的方式，把它们转化为数学公式即可。

### 3.3 DP 与记忆化递归（自顶向下）有什么区别？

本质是一样的，都在避免重复计算：**记忆化递归**自顶向下，从结果往前推、遇到算过的直接取；**DP（自底向上）** 从 `dp[0]` 一步步稳扎稳打算到最终结果。JS 中递归有爆栈 (Stack Overflow) 风险，处理大规模数据时强烈推荐把记忆化递归重构为迭代形式的 DP。

### 3.4 什么是状态压缩？必须写吗？

若发现 `dp[i]` 仅依赖 `dp[i-1]` 或 `dp[i-2]`，那么前面算过的一大串数据都已无用，可以不用数组、只用几个变量存储前置状态，把空间从 $O(n)$ 降到 $O(1)$，这就是状态压缩。面试中先写出 O(n) 的数组版本保证正确性，再作为加分项展示优化为 O(1)。

### 3.5 什么时候用一维 `dp[i]`，什么时候用二维 `dp[i][j]`？

取决于状态由几个变量决定：只需要「位置」一个维度（爬楼梯、打家劫舍、LIS 基础版）就写一维；需要两个相互独立的维度（LCS / 编辑距离的两个字符串、背包的容量与物品、区间 DP 的左右端点）就写二维。注意二维**不一定**真要开二维数组，能滚动压缩成一维就压缩——先按最直白的维度写对，再观察 `dp[i][j]` 依赖哪些格子，能压就压。

### 3.6 背包问题为什么 0-1 背包要倒序，完全背包却要正序？

一维数组把「物品」这一维滚掉了。0-1 背包要求每件物品最多用一次，**倒序**时 `dp[j - w]` 读到的是本轮尚未更新的旧值（相当于上一行的状态）；**正序**时 `dp[j - w]` 可能已被本轮更新，会导致一件物品被反复取用，退化成完全背包。记口诀「**0-1 倒序，完全正序**」，忘了就画一张两行的小表手动推一遍。

### 3.7 LIS 的 `O(n log n)` 解法怎么理解？

用 `tails` 数组维护「长度为 `len` 的递增子序列的最小结尾值」。遍历每个数 `x`，在 `tails` 里二分找到第一个 `>= x` 的位置并替换；若 `x` 比所有结尾都大，就追加到末尾、长度加一。因为 `tails` 始终有序、可以二分，整体达到 $O(n \log n)$。注意 `tails` **不是最终结果本身**，它只记录「各长度对应的最小结尾」，只有它的**长度**才是 LIS 长度。
