# 深度优先遍历 (Depth-First Search, DFS)

## 1. DFS 核心概览

深度优先遍历（DFS）是一种用于遍历或搜索树或图的算法。它的核心思想是：**“不到黄河心不死”。从起始节点开始，沿着一条路径不断向下钻取，直到遇到叶子节点（或死胡同），然后退回（回溯）到上一个分叉口，继续探索下一条路径。**

> **通俗理解：** 走迷宫时，你一直贴着右边的墙壁走，遇到死胡同就退回上一个路口，换一条路继续贴着墙壁走，直到走遍整个迷宫。

### 1.1 DFS 的核心利器：栈 (Stack)

与 BFS 依赖“**队列**”不同，DFS 极其依赖**栈（后进先出 LIFO）**。
在实际编码中，DFS 有两种实现方式：

1.  **隐式栈（递归）：** 利用 JavaScript 引擎自身的“**函数调用栈（Call Stack）**”。代码极其简洁优雅，是日常开发和面试的首选。
2.  **显式栈（迭代）：** 手动创建一个数组 `[]` 模拟栈。主要用于树极深、递归容易爆栈的极端场景。

### 1.2 DFS 的王牌应用场景

| 应用场景                        | 详细说明                                                                                                            |
| :------------------------------ | :------------------------------------------------------------------------------------------------------------------ |
| **连通性问题**                  | 寻找图中有多少个独立连通的区域（如著名的“**岛屿数量**”问题）。                                                      |
| **寻找所有路径**                | 走迷宫找寻**所有**可行的路径（即之前探讨过的回溯算法）。                                                            |
| **树的各类遍历**                | 前序遍历（根左右）、中序遍历（左根右）、后序遍历（左右根）。                                                        |
| **拓扑排序 / 环检测**           | 判断一个图中是否存在死循环（如检测 NPM 包的循环依赖）。拓扑排序可用「DFS 后序遍历的逆序」实现，环检测则用三色标记。 |
| **连通分量 / 朋友圈**           | 数图中有多少个互不相连的组（如省份数量、朋友圈），每个未访问点发起一次 DFS 就得到一个分量。                         |
| **二叉树的所有路径 / 路径总和** | 枚举「从根到叶」的所有路径，或判断是否存在和为 `target` 的路径（递归天然携带路径状态）。                            |
| **洪水填充 (Flood Fill)**       | 从某点出发，把相连的同色区域整片染色（如图像渲染、扫雷展开、边框着色）。                                            |
| **记忆化搜索**                  | 在 DFS 递归结构上加一层缓存，避免重复计算相同子问题，本质是「自顶向下的动态规划」。                                 |
| **回溯与剪枝**                  | 搜索所有方案，并在中途砍掉不可能产生答案的分支（如全排列、组合总和、N 皇后）。                                      |

### 1.3 DFS 的高频术语与遍历位置

- **隐式栈 / 显式栈**：递归依赖引擎的调用栈（隐式），迭代则用数组手动模拟（显式），后者用于缓解深度过大导致的爆栈。
- **回溯 (Backtracking)**：DFS 的一种特殊形式，核心套路是「做出选择 → 递归搜索 → 撤销选择」，用于枚举所有方案。
- **剪枝 (Pruning)**：在递归中途提前 `return`，砍掉不可能产生答案的分支，是回溯的常用加速手段。
- **三色标记**：白色 = 未访问，灰色 = 当前递归栈中，黑色 = 已完成。DFS 中若走到**灰色**节点，说明存在后向边，即有环。
- **记忆化 (Memoization)**：用数组或 `Map` 缓存子问题的结果，避免同一状态被反复计算，本质是自顶向下的动态规划。
- **三种遍历位置**：进入节点时是**前序**（自顶向下传参），遍历完左子树回到节点时是**中序**（对二叉搜索树可得到有序序列），离开节点前是**后序**（自底向上汇总、撤销状态）。

## 2. 经典 DFS 场景与 JavaScript 实现

### 2.1 二叉树的基础遍历 (Tree DFS)

在二叉树中，DFS 最经典的体现就是前、中、后序遍历。由于树没有环，我们不需要担心走回头路。

#### JavaScript 代码实现 (递归版前序遍历)

```js
/**
 * 二叉树前序遍历 (DFS - 根、左、右)
 * @param {TreeNode} root
 * @return {number[]}
 */
function preorderTraversal(root) {
  const result = []

  // 定义 DFS 递归函数
  function dfs(node) {
    if (!node) return // 终止条件：遇到空节点，停止下钻

    result.push(node.val) // 1. 先处理当前节点 (根)
    dfs(node.left) // 2. 疯狂向左子树下钻 (左)
    dfs(node.right) // 3. 左边走不通了，再向右子树下钻 (右)
  }

  dfs(root)
  return result
}
```

### 2.2 网格/图的 DFS：岛屿数量 (Number of Islands)

这是 LeetCode 上最经典的图论 DFS 题目。
**题目描述：** 给你一个由 `'1'`（陆地）和 `'0'`（水）组成的的二维网格，请你计算网格中岛屿的数量。岛屿总是被水包围，并且每座岛屿只能由水平方向和/或竖直方向上相邻的陆地连接形成。

**核心逻辑：** 遍历整个网格，一旦遇到 `'1'`，说明发现了一个新岛屿（数量+1）。然后立刻启动 DFS，像病毒感染一样，把与它相连的所有 `'1'` 都变成 `'0'`（即标记为已访问），防止后续遍历时重复计算。

#### JavaScript 代码实现

```js
/**
 * 岛屿数量
 * @param {character[][]} grid
 * @return {number}
 */
function numIslands(grid) {
  if (!grid || grid.length === 0) return 0

  let count = 0
  const rows = grid.length
  const cols = grid[0].length

  // 定义 DFS 感染函数
  function dfs(r, c) {
    // 终止条件：越界，或者是水 ('0')，停止探索
    if (r < 0 || c < 0 || r >= rows || c >= cols || grid[r][c] === '0') {
      return
    }

    // 【关键】将当前陆地变成水 (标记为已访问)，防止死循环！
    grid[r][c] = '0'

    // 向四个方向继续深度感染
    dfs(r - 1, c) // 上
    dfs(r + 1, c) // 下
    dfs(r, c - 1) // 左
    dfs(r, c + 1) // 右
  }

  // 遍历整个网格找陆地
  for (let i = 0; i < rows; i++) {
    for (let j = 0; j < cols; j++) {
      if (grid[i][j] === '1') {
        count++ // 发现新岛屿
        dfs(i, j) // 启动 DFS，把这整座岛屿全部“击沉”
      }
    }
  }

  return count
}
```

### 2.3 回溯与状态撤销：路径总和 (Path Sum)

纯 DFS 只关心「走没走过」，而回溯必须在离开节点时**把状态恢复原样**，才能正确地探索另一条分支。这个「撤销」动作恰好发生在**后序位置**（处理完子树、离开当前节点之前）。

**题目描述：** 给你二叉树的根节点 `root` 和一个整数目标 `targetSum`，返回所有「从根节点到叶子节点」且路径和等于 `targetSum` 的路径。

#### JavaScript 代码实现

```js
/**
 * 路径总和 II：返回所有从根到叶且和等于 targetSum 的路径
 * @param {TreeNode} root
 * @param {number} targetSum
 * @return {number[][]}
 */
function pathSum(root, targetSum) {
  const result = []
  const path = []

  function dfs(node, remain) {
    if (!node) return

    // 【前序位置】做出选择：把当前节点纳入路径
    path.push(node.val)
    remain -= node.val

    // 是叶子且剩余和为 0，说明找到一条合法路径
    if (!node.left && !node.right && remain === 0) {
      // 🚨 必须拷贝一份，否则会被后续的撤销操作污染
      result.push([...path])
    }

    dfs(node.left, remain)
    dfs(node.right, remain)

    // 【后序位置】撤销选择：离开节点前把它移出路径（回溯的核心）
    path.pop()
  }

  dfs(root, targetSum)
  return result
}
```

> [!TIP]
> 判断该写「纯 DFS」还是「回溯」的信号：如果题目只要遍历、计数或连通性，用 `visited` 标记后**不用还原**（如岛屿数量）；如果要**枚举所有方案**，就必须成对地写「选择」与「撤销选择」（如全排列、组合总和、N 皇后）。

### 2.4 递归 DFS vs 显式栈迭代 DFS

递归写法简洁，但受引擎调用栈深度限制（通常只有几千层），遇到超深的链式结构会抛出 `RangeError: Maximum call stack size exceeded`。此时可以手动用数组当栈，把递归改写成迭代。以二叉树前序遍历为例：

#### JavaScript 代码实现

```js
/**
 * 二叉树前序遍历 (显式栈迭代版)
 * @param {TreeNode} root
 * @return {number[]}
 */
function preorderTraversalIterative(root) {
  if (!root) return []

  const result = []
  const stack = [root]

  while (stack.length > 0) {
    const node = stack.pop()
    result.push(node.val) // 访问当前节点

    // 栈是后进先出：先压右子节点，弹出时才会先处理左子节点
    if (node.right) stack.push(node.right)
    if (node.left) stack.push(node.left)
  }

  return result
}
```

- **与递归的差异**：递归版靠函数调用栈自动保存「回溯点」，迭代版必须自己把待访问节点压进数组，写法略繁琐，但不受调用栈深度限制。
- **前序 / 后序最容易迭代**：前序是「根入栈，弹出后先压右再压左」；后序可先按「根右左」前序，最后整体反转。**中序**需要一路把左子节点压栈，稍微复杂，但仍是标准套路。
- **网格 / 图用迭代 DFS 时**，应在压栈那一刻就标记 `visited`，避免同一个节点被重复压入。

## 3. 常见问题深度剖析 (FAQ)

### 3.1 DFS 和回溯算法（Backtracking）到底是什么关系？

回溯是 DFS 的一种特殊形式。DFS 强调“**结构上的遍历**”（把每个角落都看一遍），回溯强调“**状态的记录与撤销**”（退回时把状态恢复原样）。岛屿数量中把 `'1'` 变成 `'0'` 后没有改回，是纯 DFS；若探索完还要改回，就是回溯。

### 3.2 二叉树的 前序、中序、后序 为什么都属于 DFS？

因为它们都靠递归一路下钻到底，唯一区别是“**处理当前节点数据的时机**”：

- 第一次经过节点就处理：前序。
- 左子树处理完、退回该节点时处理：中序。
- 左右子树都处理完、离开节点前处理：后序。

### 3.3 DFS 为什么不能直接求最短路？

DFS 是“**一条路走到黑**”，第一次到达终点并不保证路径最短，它可能刚好扎进了最绕的分支；要拿最短路只能搜完全部路径再取最小值，复杂度会膨胀到指数级。正解是无权图用 BFS，带权图用 Dijkstra / Bellman-Ford。

### 3.4 递归深度太大导致爆栈（`RangeError: Maximum call stack size exceeded`）怎么办？

JS 引擎调用栈通常只有几千层，链状图、长路径回溯很容易击穿。应对办法：

- 改成显式栈迭代（见 2.4 节），彻底摆脱调用栈限制。
- 控制递归深度，或把问题改造成 BFS / 并查集（如网格连通性）。
- 慎用尾递归优化，绝大多数 JS 引擎并不实现它。

### 3.5 前序、中序、后序分别适合做什么？

- 前序（进入节点时）：自顶向下传递信息——记录路径、累加和、求深度、复制或序列化一棵树。
- 中序（遍历完左子树后）：仅对二叉树有意义，配合 BST 可得到升序序列，常用于验证 BST。
- 后序（离开节点前）：自底向上汇总子树结果——求树高、子树和、判断平衡，以及回溯时撤销状态。

### 3.6 如何用 DFS 判断环？

- 无向图：DFS 时若遇到一个“**已访问且不是当前节点父节点**”的邻居，说明有环（也可用并查集）。
- 有向图：必须用三色标记。白色未访问、灰色在当前递归栈中、黑色已处理完；走到灰色节点说明存在后向边，即有环，走到黑色节点只是前向 / 交叉边，不构成环。

### 3.7 如何一眼判断该写纯 DFS 还是回溯？

- 纯 DFS：只关心“**访问过没有**”，用 `visited` 或原地标记后不回退（如岛屿数量、连通分量、洪水填充）。
- 回溯：要枚举所有方案，必须成对地写“**做出选择**”与“**撤销选择**”，结果随路径栈实时记录（如全排列、组合总和、N 皇后）。

一句话：回溯 = DFS + 状态撤销。

### 3.8 网格 DFS 的原地标记技巧是什么？

网格题常用“**原地修改**”替代额外的 `visited` 数组：把访问过的陆地直接改成水（`'1'` → `'0'`）、取负号或染成特殊值，省下 $O(m \times n)$ 的空间。代价是会破坏输入数据：要求保留原网格时得改用独立 `visited`；若后续需要回溯，必须在后序位置把原值改回来，否则会污染其他分支。
