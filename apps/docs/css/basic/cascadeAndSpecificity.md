# 层叠与特异性 (Cascade & Specificity)

CSS 全称「层叠样式表」，其中「层叠 (Cascade)」才是这门语言的灵魂。当多条样式规则同时命中同一个元素、却给出相互矛盾的声明时，浏览器必须裁决「**到底谁说了算**」。层叠与特异性（Specificity）就是这套裁决规则的总和。

**一句话理解**：**「特异性决定『谁能赢』，层叠顺序决定『平局时谁优先』，`!important` 和 `@layer` 则是两把改变游戏规则的『特权卡』。」**

## 1. 层叠 (Cascade)：样式从哪来、谁先谁后

一个元素最终呈现的样式，其实是来自多个「来源」的声明层层叠加的结果。当声明不冲突时，它们和平共存；一旦冲突，浏览器按照下面的**优先级从低到高**逐级覆盖。

### 1.1 三大来源与优先级

| 优先级（低 → 高） | 来源                                   | 说明                                                              |
| ----------------- | -------------------------------------- | ----------------------------------------------------------------- |
| 1                 | 用户代理样式表 (User Agent Stylesheet) | 浏览器默认样式，如 `<a>` 的蓝色、`<h1>` 的加粗、`<ul>` 的圆点。   |
| 2                 | 用户样式表 (User Stylesheet)           | 用户通过浏览器扩展或设置注入的自定义样式，日常开发中较少见。      |
| 3                 | 作者样式表 (Author Stylesheet)         | 我们写的 CSS，包含外部文件、`<style>` 和内联样式。                |
| 4                 | 作者样式表中的 `!important`            | 作者声明中带 `!important` 的规则，优先级极高。                    |
| 5                 | 用户样式表中的 `!important`            | 用户的 `!important` 甚至能压过作者的 `!important`（无障碍场景）。 |

**核心结论**：日常开发中，我们主要关心「作者样式表」内部的竞争，也就是下面要讲的特异性。

### 1.2 一张图看懂完整裁决流程

```
两条声明冲突时，浏览器依次比较：

① 来源 (Origin)  → 用户 !important > 作者 !important > 作者 > 用户 > UA
        ↓ 相同
② 层叠层 (@layer) → 未分层 > 后声明的层 > 先声明的层
        ↓ 相同
③ 特异性 (Specificity) → 权重四元组高者胜
        ↓ 相同
④ 书写顺序 (Source Order) → 后写覆盖先写
```

## 2. 特异性 (Specificity)：权重计算

当来源相同（都是作者样式）时，浏览器通过「特异性」给每条选择器打一个权重分，**分数高者获胜**。

### 2.1 权重模型 (a, b, c, d)

特异性通常记作一个四元组 `(a, b, c, d)`，从左到右逐位比较，**高位碾压低位**（`a` 最高，`d` 最低）：

| 位  | 对应选择器              | 举例                              |
| --- | ----------------------- | --------------------------------- |
| `a` | 内联样式 (`style` 属性) | `<div style="...">`               |
| `b` | ID 选择器               | `#app`                            |
| `c` | 类 / 属性 / 伪类选择器  | `.box`、`[type="text"]`、`:hover` |
| `d` | 元素 / 伪元素选择器     | `div`、`p`、`::before`            |

> 注意：通用选择器 `*`、组合器 (`>`、`+`、`~`、空格) 以及 `:where()` 的权重为 **0**，不参与累加。

### 2.2 计算示例

```css
/* (0, 0, 0, 1) —— 1 个元素 */
p { color: black; }

/* (0, 0, 1, 1) —— 1 类 + 1 元素 */
.article p { color: gray; }

/* (0, 1, 0, 0) —— 1 个 ID */
#title { color: blue; }

/* (1, 0, 0, 0) —— 内联样式 */
<div id="title" class="article" style="color: red">
```

最终 `#title` 里的文字是**红色**，因为内联样式 `(1,0,0,0)` 直接碾压其他三者。

### 2.3 复合选择器的权重累加

每条选择器的权重是其**所有组成部分之和**：

```css
/* 权重 = (0, 1, 2, 1) */
/* 1 个 ID (#nav) + 2 个类 (.menu .item) + 1 个元素 (li) */
#nav .menu li.item {
  color: red;
}

/* 权重 = (0, 1, 1, 0) —— 较低，输给上面 */
#nav .menu li {
  color: blue;
}
```

## 3. 现代选择器的权重规则

### 3.1 `:is()` / `:not()` / `:has()`：取参数中最高的权重

这三个「逻辑伪类」的权重**等于其参数列表中特异性最高的那一项**：

```css
/* :is() 的权重 = 其中最高者 = .special 的 (0,0,1,0) */
:is(p, .special, #hero) {
  color: red;
} /* 权重 (0,0,1,0)，而非 0 */

/* :not() 同理，取参数中最高项 */
:not(.exclude) {
  color: red;
} /* 权重 (0,0,1,0) */
```

### 3.2 `:where()`：权重恒为 0

`:where()` 及其参数**权重永远为 0**，是「零权重」的利器——写出来的默认样式可以被任意其他规则轻松覆盖：

```css
/* 权重 (0,0,0,0)，任何带权重的规则都能覆盖它 */
:where(.theme, #reset) p {
  margin: 0;
}
```

**实战价值**：用 `:where()` 写「全局 reset / 默认主题」，业务代码无需高权重就能覆盖，避免特异性军备竞赛。

### 3.3 `:nth-child()` 等结构伪类

结构伪类（`:nth-child`、`:first-child`、`:last-of-type` 等）按**类选择器**计权重，即 `(0,0,1,0)`：

```css
li:nth-child(2) {
  color: red;
} /* (0,0,1,1)：1 伪类 + 1 元素 */
```

## 4. `!important`：暴力翻盘

`!important` 会**绕过正常特异性比较**，直接跳到作者样式的最高优先级，但仍有其内部规则：

```css
p {
  color: red !important;
}
p {
  color: blue;
} /* 被上面的 !important 覆盖 */
```

### 4.1 `!important` 的内部竞争

- `!important` 之间同样比较**特异性**，特异性高者胜。
- 一个 `!important` 可以压过普通内联样式。
- 要覆盖另一个 `!important`，只能写更具体的 `!important`，或借助 `@layer` 调低对方的层优先级。

### 4.2 为什么说它是「毒药」

`!important` 破坏了层叠的直觉——后续想改样式只能继续叠加 `!important`，形成恶性循环，代码不可维护。**唯一合理场景**：覆盖第三方库（UI 组件库、富文本编辑器）的样式。治理优先级混乱的正确工具是下一节的 `@layer`。

## 5. 层叠层 (@layer)：给「优先级」重新洗牌

`@layer` 允许开发者**人为给样式分组并指定组的优先级**，从根源上治理特异性战争。它与特异性是两套正交的机制：**先比层，层相同才比特异性**。

```css
/* 声明层顺序：后声明的层优先级更高 */
@layer reset, base, theme, components;

@layer reset {
  * {
    margin: 0;
    padding: 0;
  }
}
@layer theme {
  .btn {
    background: blue;
  } /* 权重低，但所在层靠后 */
}
/* 未分层样式永远比所有 @layer 高 */
.btn {
  background: red;
}
```

**规则速记：**

- **未分层的作者样式 > 所有 `@layer` 样式**。
- `@layer` 之间按声明顺序，**后声明者优先**。
- 同一层内，仍回到「特异性 → 后写覆盖」的裁决。
- 被「早声明层」里的高特异性规则，压不过「晚声明层」里的低特异性规则。

> 更多 `@layer` 细节可参考 [级联层](/css/advanced/project/cascadeLayer)。

## 6. 继承 (Inheritance)：与层叠的边界

继承是「**属性值的流动**」，不是「样式竞争」。两者常被混淆，务必分清：

| 维度 | 层叠 (Cascade)         | 继承 (Inheritance)               |
| ---- | ---------------------- | -------------------------------- |
| 本质 | 冲突声明的裁决机制     | 属性值从父元素传递到子元素       |
| 对象 | 同一元素的**多条规则** | 父元素 → 子元素的**单条规则**    |
| 权重 | 有（特异性四元组）     | 无权重，继承来的值「优先级最低」 |

**关键结论**：继承来的样式**永远输给**任何直接写在元素上的声明，哪怕直接声明是 `* { }` 这种零权重选择器。

```css
body {
  color: red;
} /* 子元素继承 red */
* {
  color: black;
} /* 直接命中子元素，即使权重 0，也覆盖继承的 red */
```

### 6.1 控制继承的关键字

| 关键字         | 作用                                           |
| -------------- | ---------------------------------------------- |
| `inherit`      | 强制继承父元素的值（即使该属性默认不继承）。   |
| `initial`      | 使用该属性的「初始值」（规范默认值）。         |
| `unset`        | 可继承属性→继承，非继承属性→初始值。           |
| `revert`       | 回退到「上一层来源」的样式（如用户代理样式）。 |
| `revert-layer` | 回退到上一层层叠层的样式。                     |

```css
.box {
  color: unset; /* color 可继承 → 等同 inherit */
  border: unset; /* border 不可继承 → 等同 initial（无边框） */
}
```

> 详见 [继承](/css/basic/inheritance)。

## 7. 常见问题 (FAQ)

### 7.1 为什么我给 `.box p` 写的颜色不生效？

大概率被更高权重的选择器压住了（如 `#content p` 或内联样式）。用 DevTools 的 Elements 面板查看该元素的 Computed 样式，能看到哪条规则胜出、哪条被划了删除线。

### 7.2 权重可以「进位」吗？

**不能**。`(0,0,1,0)` 永远大于 `(0,0,0,99)`——哪怕你写 99 个元素选择器，也压不过 1 个类选择器。四元组是**逐位比较**，不是十进制累加。

### 7.3 为什么内联样式能被 `!important` 覆盖？

因为 `!important` 改变了**来源优先级**（作者 `!important` > 作者普通内联），它和特异性是两套维度。但反过来，内联样式（权重 `a` 位）却压不过它自己来源层级之上带 `!important` 的规则。

### 7.4 `:is(#a, .b)` 的权重是多少？

取参数中最高项 `#a` 的权重，即 `(0,1,0,0)`，而不是「按匹配结果动态决定」。这是很多人的误区。

### 7.5 如何优雅地提升/降低权重？

- **降低**：用 `:where()`（零权重）、`@layer`、避免 ID 和过深嵌套、用继承代替重复声明。
- **提升**：增加类选择器，或提高所在层叠层的优先级；慎用 `!important`。

## 8. 总结

- 层叠顺序：**来源优先级**（UA < 用户 < 作者 < 作者 !important）。
- 同源竞争看**特异性**：`内联 > ID > 类/属性/伪类 > 元素/伪元素`。
- `:is()/:not()/:has()` 取参数最高权重，`:where()` 恒为 0。
- 平局看**书写顺序**：后写覆盖先写；继承值无权重，永远最低。
- `!important` 是核武器，**能不用就不用**；`@layer` 才是治理优先级混乱的现代解药。
