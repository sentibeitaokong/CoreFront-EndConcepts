# 构造器模式

## 1. 核心概念

构造器模式是一种**创建型设计模式**。它的目的是通过一个特定的函数（或类）来初始化新创建的对象，并为对象分配内存和属性。

[width(13,87)]

| 维度         | 描述                                                                                                                                                                       |
| :----------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **核心定义** | 定义一个“**构造函数 / 类**”，通过 `new` 调用它来批量创建结构一致的实例：属性放在实例上，方法放在原型上共享。                                                               |
| **核心意图** | 为特定类型的对象定义一套“**蓝图**”，并批量生产具有相同结构的实例。                                                                                                         |
| **关键角色** | 1. **构造器 (Constructor)**：负责初始化对象的函数或类；<br>2. **实例 (Instance)**：被创建出来的对象；<br>3. **原型对象 (Prototype)**：存放共享方法的仓库，被所有实例引用。 |
| **主要优点** | 1. **代码复用**：避免重复写对象字面量；<br>2. **结构统一**：确保同一类对象拥有相同的属性和方法名；<br>3. **易于扩展**：通过原型链或继承轻松增加功能。                      |
| **主要缺点** | 1. 如果不正确地使用原型（Prototype），会导致每个实例都冗余地持有相同的方法，造成内存浪费；<br>2. 与继承强耦合，层级过深时难以维护。                                        |

**什么时候该用、什么时候不该用**

[width(22,38,40)]

| 判断维度             | 适用构造器模式                                 | 不建议使用                                                   |
| :------------------- | :--------------------------------------------- | :----------------------------------------------------------- |
| **对象数量**         | 需要创建大量结构相同、仅初始数据不同的对象     | 只创建一个一次性对象，直接用对象字面量 `{}` 更简单           |
| **是否需要状态**     | 每个实例需要各自独立的属性状态                 | 纯粹无状态的工具函数，用一个 `const utils = { ... }` 即可    |
| **是否需要共享行为** | 多个实例共享同一套方法（放到原型上，节省内存） | 只是想把这些相关函数挂在一起当“**命名空间**”，不需要多个实例 |
| **创建逻辑复杂度**   | 属性初始化直接、无分支                         | 创建逻辑复杂、要根据入参决定造哪种对象，应改用**工厂模式**   |

## 2. 构造器模式的演进

### 2.1 传统函数式构造器 (ES5 及以前)

在 ES6 之前，JavaScript 使用普通函数配合 `new` 关键字来实现构造器。

```js
function Hero(name, role) {
  // 1. 属性定义在实例上
  this.name = name
  this.role = role

  // 2. ❌ 错误做法：将方法定义在构造函数内部
  // 这会导致每个实例都创建一份该函数的副本，浪费内存
  this.sayHello = function () {
    console.log(`我是${this.name}，我的职业是${this.role}`)
  }
}

// 3. ✅ 正确做法：将方法定义在原型对象上
Hero.prototype.attack = function () {
  console.log(`${this.name} 发起了进攻！`)
}

const garen = new Hero('盖伦', '战士')
garen.attack()
```

### 2.2 现代类写法 (ES6 Class)

ES6 引入了 `class` 关键字，这实际上是构造函数和原型模式的**语法糖**，让代码看起来更具条理。

```js
class Car {
  // 构造器：负责初始化属性
  constructor(brand, price) {
    this.brand = brand
    this.price = price
  }

  // 方法会自动添加到原型链上，所有实例共享
  drive() {
    console.log(`${this.brand} 正在行驶...`)
  }
}

const myCar = new Car('Tesla', 300000)
myCar.drive()
```

## 3. `new` 关键字到底做了什么？

理解构造器模式的关键在于理解 `new` 的执行过程。当你调用 `new Hero(...)` 时，发生了以下四件事：

- **创建一个全新的空对象**（例如 `{}`）。
- **链接原型**：将这个新对象的 `__proto__` 指向构造函数的 `prototype` 属性。
- **绑定 `this` 并执行**：执行构造函数，将其中的 `this` 指向这个新对象，从而为它添加属性。
- **返回新对象**：如果构造函数没有返回其他对象，则默认返回这个新创建的对象。

```js
function New() {
  var obj = new Object()
  //取出第一个参数
  var constructor = Array.prototype.shift.call(arguments)
  obj.__proto__ = constructor.prototype
  var ret = constructor.apply(obj, arguments)
  // 如果构造函数中return 了对象则返回对象
  return typeof ret === 'object' ? ret : obj
}
```

## 4. 典型应用场景

[width(15,85)]

| 场景                | 说明（真实库 / 框架里的用法）                                                                     |
| :------------------ | :------------------------------------------------------------------------------------------------ |
| **UI 组件实例**     | 每个组件实例持有一份独立的 `props` / `state`，方法在原型或类上共享（如 Backbone 的 `View`）。     |
| **数据模型 / 实体** | `new User(data)`、`new Order(data)` 把接口返回的 JSON 包装成带方法的对象，统一数据的读写入口。    |
| **自定义错误**      | `class MyError extends Error` 后用 `new MyError(...)` 抛出，能带上堆栈和自定义字段。              |
| **原生内置对象**    | `new Date()`、`new Map()`、`new Set()`、`new URL()`、`new Promise()` 全部是构造器。               |
| **浏览器 Web API**  | `new Image()`、`new Audio()`、`new XMLHttpRequest()`、`new WebSocket(url)`。                      |
| **第三方库封装**    | 用类包装插件实例，如 `new Swiper(el)`、`new Chart(ctx, config)`，一个实例对应一份独立的内部状态。 |

## 5. 关键语言特性与易错点

构造器模式在 JS 里依赖下面这些语言机制，它们同时也是面试与踩坑的高发区。

[width(18,38,44)]

| 特性 / API             | 说明                                                                 | 易错点                                                                             |
| :--------------------- | :------------------------------------------------------------------- | :--------------------------------------------------------------------------------- |
| `new` 运算符           | 创建实例、链接原型、绑定 `this`、返回对象。                          | 漏写 `new` 时 `this` 指向 `window`（非严格模式）或 `undefined`（严格模式）。       |
| `class`                | 构造函数 + 原型的语法糖，方法默认挂在 `prototype` 上且**不可枚举**。 | `class` 不会提升（有暂时性死区），且必须用 `new` 调用，否则直接报错。              |
| 类字段 `field = value` | 在实例上定义属性，每个实例各有一份。                                 | 写成箭头函数字段 `onClick = () => {}` 会为**每个实例**创建一份函数，破坏内存共享。 |
| `new.target`           | 判断函数是否通过 `new` 调用，可用于防止漏写 `new`。                  | 只在普通函数 / 类里可用，箭头函数里取到的是外层的值。                              |
| `instanceof`           | 沿原型链判断实例归属。                                               | 跨 `iframe` / realm 时失效（两边原型来自不同的全局环境）。                         |
| `Object.create(proto)` | 指定原型创建对象，是纯原型式的创建手段。                             | 它**不会**执行构造器逻辑，属性需要另外初始化。                                     |

## 6. 常见问题 (FAQ)

### 6.1 如果调用构造器时忘记写 `new` 会怎样？

这是一个非常经典且危险的问题。

- 在**非严格模式**下：`this` 会指向全局对象（浏览器里是 `window`），你会无意中修改全局变量，且函数不会返回对象（得到 `undefined`）。
- 在**严格模式** (`'use strict'`) 下：`this` 是 `undefined`，尝试给它赋值会直接抛出错误。
- **解决方案**：现代开发中建议始终使用 `class`，因为 `class` 强制要求使用 `new`，否则会直接报错。

### 6.2 为什么要把方法写在 `prototype` 上，而不是 `constructor` 内部？

**为了内存性能。**

- 写在 `constructor` 内：每个实例都会拥有一份独立的方法函数副本。如果有 1000 个实例，内存中就有 1000 个一模一样的函数。
- 写在 `prototype` 上：所有实例共用同一个函数引用。无论有多少个实例，内存中只占一份空间。

### 6.3 构造函数可以有 `return` 吗？

可以，但要小心。

- 如果返回的是**原始类型**（如数字、字符串）：会被忽略，依然返回新创建的实例。
- 如果返回的是一个**新对象**：那么 `new` 的结果将不再是原本打算创建的实例，而是你 `return` 出来的那个对象。

### 6.4 箭头函数可以作为构造器吗？

**绝对不可以。**

- 原因一：箭头函数没有自己的 `this`，它的 `this` 是在定义时捕获的上下文。
- 原因二：箭头函数没有 `prototype` 属性。
- 尝试对箭头函数使用 `new` 会导致脚本抛出 `TypeError`。
